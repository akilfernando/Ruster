# Shared 3D viewport

The bounded Rust/wgpu Vulkan renderer is used by the scene editor and this independent binary. Both draw the same scene transforms with the same pipeline; the binary has no editor or MCP dependency. It currently uses eframe for window/device/presentation and UI embedding. This is a shared rendering path, not yet a toolkit-independent application kit.

```sh
cargo run --locked -p ruster-render
cargo run --locked -p ruster-scene -- demo /tmp/ruster-scene.json
cargo run --locked -p ruster-render -- --scene /tmp/ruster-scene.json --ticks 10 --frames 90
cargo run --locked --release -p ruster-render -- --objects 3 --frames 180
cargo run --locked --release -p ruster-render -- --objects 256 --frames 180
```

Use a new filename for `demo`; existing destinations are protected. Use a valid saved scene path for `--scene`. `--objects 256` generates a 16×16 grid of unit-cube instances; `--objects 3` uses the default three-object scene. These options cannot be combined with `--scene`. `--ticks 0..10000` advances the shared static `Preview` lifecycle before rendering: it counts explicit ticks, without application-specific animation. The shutdown summary includes scene fingerprint, revision and tick for comparison with CLI/editor. `--frames 1..10000` repaints and exits after at least that many rendered scene frames. Without it the window sleeps when no redraw is requested.

Left-click selects the nearest visible transformed surface, using inverse-model ray/triangle intersection for imported meshes and ray/box intersection for procedural cubes, including perspective and depth order. Right-drag orbits; wheel zooms; Fit frames the scene bounds. Camera navigation is frontend session state, separate from saved authored object transforms. Selection lightens each selected object's material. The opaque material currently uses RGB only; stored alpha is reserved and does not enable transparency.

## Embedding and ownership

Call `configure_setup(&mut WgpuSetupCreateNew)` before device creation to request optional `TIMESTAMP_QUERY` and `TEXTURE_ADAPTER_SPECIFIC_FORMAT_FEATURES` only when supported. Restrict instance backends to `wgpu::Backends::VULKAN` in the host. After creation, call `install(&RenderState)` once; retain the returned `MetricsHandle` if diagnostics are needed. Call `viewport(&mut egui::Ui, &Scene, Option<&str>) -> Option<String>` to paint and receive a newly selected stable ID. Inputs must satisfy `Scene::validate()`.

For frontend-owned manipulation overlays, call `viewport_interactive(ui, scene, selected: &[&str], meshes, navigation_enabled) -> ViewportInteraction`. It paints through the same callback and returns the viewport `rect`, egui `response`, newly `picked` stable ID, and separate column-major `view`, `projection` and `gizmo_projection` matrices. `projection` uses wgpu's right-handed 0..1 clip depth; `gizmo_projection` uses right-handed -1..1 clip depth for overlay toolkits with that convention. Their projected screen x/y positions match. Paint overlays after this call, using its exact viewport rectangle and matching projection convention. The host owns gesture state, applies object edits and suppresses scene picks consumed by an overlay. Pass `navigation_enabled = false` during a gesture to freeze right-drag orbit, wheel zoom and Fit. This API highlights every selected ID within the existing 256-object scene bound; it does not add GPU resources or change mesh/upload ownership. Existing `viewport` and `viewport_with_assets` signatures retain their single-selection behavior and navigation controls.

The current integration supports one viewport per eframe renderer. Camera state is isolated by UI/scene ID. A persistent indexed cube (24 vertices, 36 indices), retained per-asset vertex/index buffers and a geometrically grown instance buffer feed one indexed instanced draw per referenced mesh ID. GPU buffers reuse stable immutable `Arc<Mesh>` snapshots and are replaced after explicit content refresh; unused assets are evicted. The cache enforces 64 meshes, 32768 triangles per mesh and 32 MiB aggregate imported mesh payload, matching AssetStore bounds. It does not silently truncate geometry. Each instance contains its model matrix, inverse-transpose normal matrix and color; fixed-axis rotation applies X then Y then Z. No raw Vulkan or unsafe Rust is used here. wgpu owns device/resource synchronization and eframe owns surface/device lifecycle. Dropping the host drops resource handles; pending timestamp callbacks retain only their readback buffer and diagnostics until completion.

`egui_wgpu::CallbackTrait::prepare` records an offscreen color/depth scene pass into the host encoder. `paint` composites its sampled color into egui's existing pass. The offscreen target is recreated when physical viewport dimensions, color profile or negotiated sample count change. It uses `Rgba8UnormSrgb` and matching-sample `Depth32Float`, perspective or orthographic look-at projection, backface culling and simple directional diffuse plus ambient lighting. The provisional default requests 4× MSAA; set `RUSTER_MSAA_SAMPLES=1`, `2` or `4` before launching either frontend to compare quality/cost. Installation logs requested/effective counts. Selection falls back to the highest supported count no greater than requested, requiring both color/depth sample support and color resolve support. Adapter-specific counts (notably 2×) are used only when that optional device feature is enabled; otherwise selection also intersects the guaranteed device format flags. Invalid environment values are diagnosed and use the provisional 4× request. This is an agent-selected initial quality setting, pending native quality/cost acceptance. The composite chooses linear/sRGB framebuffer output correctly. This bounded scene/composite integration gives the scene a real depth attachment without imposing an egui depth configuration on the host. With MSAA enabled, a multisampled color attachment resolves into the existing single-sample sampled color texture; multisampled color/depth contents are discarded after the pass. At 1× there is no extra color attachment or resolve. Both paths retain one composite draw and leave UI/text rendering unchanged. Shader refresh keeps the installed sample count. Physical targets scale uniformly to the device dimension limit and a 256 MiB retained attachment payload budget; the logical viewport aspect continues to control camera, gizmos and picking. Rounding introduces at most a pixel of aspect error. The cap is an agent-selected bound, excludes driver overhead and the separately counted prior-submit-fenced retiring target during resize/profile changes, and can reduce resolution on unusually large/high-DPI viewports. Multiple views and general render graphs remain outside this bounded renderer; the opt-in V3a section below supersedes the earlier SDR-only surface description; the later V1/V2 sections own materials/authored illumination/Sun shadows.

## Imported geometry and controlled shader refresh

`viewport_with_assets(ui, scene, selected, &BTreeMap<String, Arc<ruster_assets::Mesh>>)` draws stable imported references. Resolve snapshots through `ruster-assets`; keep their Arc identity stable between content operations. Existing `viewport` remains the procedural-only convenience wrapper. Camera Fit computes exact transformed vertex bounds and imported picking tests actual front-facing triangles. Missing references use the cube fallback; the host must display AssetStore/missing-reference diagnostics. The standalone `--scene` path opens its parent as the asset root, reports missing/invalid references, and offers **Refresh assets**, which explicitly re-resolves content and resets its static preview tick to zero. No background file watcher accepts changes.

`default_shader()` exposes the built-in WGSL. `refresh_shader(&RenderState, source)` synchronously builds a custom SDR candidate pipeline inside a wgpu validation error scope and swaps it only after validation succeeds. Restoring the exact built-in source switches to its retained pipeline without compilation. Source is bounded to 64 KiB UTF-8. The `vs`/`fs` entrypoints, camera uniform at group0/binding0, vertex/instance attributes, depth/cull/color target and composite pass remain fixed. Malformed WGSL and incompatible resource bindings return an actionable error while retaining the previous usable pipeline. This supports local trusted shader iteration, not arbitrary shader layouts, materials, sandboxed untrusted GPU programs or Rust hot reload. Compilation may block the UI thread; there is no background compiler or general pipeline cache.

The standalone CLI can load a trusted explicit source path initially:

```sh
cargo run --locked -p ruster-render -- --scene examples/arrangement.scene.json --shader /tmp/scene.wgsl --frames 90
```

Copy the built-in [scene.wgsl](src/scene.wgsl) before editing. Initial shader failure is reported and the built-in pipeline still renders. **Refresh scene shader** rereads that explicit path; absent `--shader`, the button reads `scene.wgsl` beside the loaded scene only when clicked. Reads are bounded before compilation. The CLI's explicit shader path is trusted and can be outside the project; the editor enforces its own project-local path policy. Shader state is session-only and does not alter scene revisions or preview snapshots.

CPU regression coverage checks imported surface picking beyond the old cube bounds, empty space inside a mesh bounding box and exact transformed fit bounds. These cases also exercise off-center picking through the exposed camera convention, matched overlay/render screen coordinates and the separate near/far clip-depth mappings. Explicit Vulkan boundary coverage is `cargo test --locked -p ruster-render shader_rejection_preserves_renderable_pipeline -- --ignored`: it accepts a valid replacement, rejects malformed and incompatible-binding candidates, then submits the retained pipeline at each supported 1×/2×/4× count, replaces attachments during pending work and drops resources before waiting for completion. Unsupported counts are explicitly reported. A portable CPU table checks color/depth/resolve fallback and attachment payload/aspect bounds. This device test complements native resize/shutdown and frontend refresh evidence; it does not prove a visual shader result.

## Diagnostics and measurement

The standalone binary prints adapter/backend on creation and a bounded summary on shutdown, including cumulative mesh buffer creations/upload payload, last-frame scene draw calls, effective MSAA count and physical target size. The built-in cube counts as one mesh creation; stable imported snapshots should add one creation each, not one per frame. These counters measure renderer payload operations, not allocator/driver transfers. First ten rendered scene frames are warmup; each CPU/GPU sample vector is capped at 4096. CPU preparation measures model/normal/color instance preparation and mesh grouping plus callback upload/target preparation and command encoding, including new GPU mesh creation on refresh. Stable mesh snapshots avoid repeated vertex/index uploads. It excludes UI layout, picking, presentation waiting and GPU execution. GPU timestamps measure the offscreen scene work, including its clear/draw and MSAA resolve; they exclude UI/composite, presentation, CPU work and readback. With an enabled built-in Sun shadow, four queries report separate depth and color intervals plus total depth-start through color-end, including the inter-pass gap. Without a depth pass only the two written color queries resolve; the shadow sample is None, not a measured zero. They use asynchronous map-on-submit readback with at most one pending sample. Therefore GPU/CPU sample counts can differ. `None` is a missing measurement, never a zero-time GPU claim. If timestamps are unavailable the renderer still runs and reports the gap explicitly.

Memory figures are resource payload estimates, not allocated VRAM: cube vertices+32-bit indices = 720 bytes (M5 used 16-bit indices and 648 bytes); imported vertices+indices = 24 bytes per vertex + 4 bytes per index; instance capacity = 128 bytes × next power-of-two object capacity (minimum one); color/depth attachment payload = physical width × height × 8 bytes at 1×, or × (4 + 8 × samples) bytes with MSAA: one 4-byte resolved color plus sample-count-scaled 4-byte color/depth. This is 20 bytes/pixel at 2× and 36 at 4×. The existing `color_depth_bytes` summary field includes the resolved color payload. Camera uniform adds 64 bytes; enabled query resolve/readback adds 32 payload bytes. These omit driver alignment, query storage, pipeline/descriptor bookkeeping, staging, swapchain, egui and process allocations. No allocation-count, total-memory or competitive-performance claim follows from them.

The 3-object and 256-object release commands establish declared initial workloads. Record hardware/driver, window size, validation state, warmup/repeats and compositor visibility when publishing samples. Hidden-workspace rendering is potentially throttled; compare matching conditions. The previous ash schematic cannot be a like-for-like 3D baseline. This implementation establishes a baseline rather than claiming an optimization win. A future cached unchanged-instance upload experiment should compare CPU preparation/upload bytes and end-to-end correctness at both workloads before introducing broader invalidation machinery.

On the local desktop, the initial title `Ruster | Shared 3D` matches the existing workspace-2 rule. Verify routing before interaction; do not switch the user's workspace or use global input. Root integration owns GPU validation, resize/shutdown and visual evidence; compile/unit success alone does not prove Vulkan lifecycle correctness.

## Primary research and tradeoffs

Sources consulted 2026-11-04; APIs also checked against installed egui-wgpu 0.37.0 and wgpu 30.0.1 source:

- [egui-wgpu callback lifecycle](https://docs.rs/egui-wgpu/latest/egui_wgpu/trait.CallbackTrait.html): shared callback resources and prepare-before-paint ordering fit one host-owned device and encoder. The integration deliberately accepts eframe coupling; a separate standalone Vulkan owner would duplicate substantial lifecycle work at this stage.
- [wgpu render-pass attachments and timestamps](https://docs.rs/wgpu/latest/wgpu/struct.RenderPassDescriptor.html) and [map-on-submit](https://docs.rs/wgpu/latest/wgpu/struct.CommandEncoder.html#method.map_buffer_on_submit): explicit color/depth reads/writes and submission-ordered readback avoid CPU blocking. Optional timestamp support is a diagnostic capability, not a rendering requirement.
- [wgpu30 validation error scopes](https://docs.rs/wgpu/30.0.0/wgpu/struct.ErrorScopeGuard.html): pipeline/module creation errors can be collected before publishing a candidate. An explicit shared bind-group/pipeline layout preserves camera binding compatibility across replacements. A controlled synchronous refresh is sufficient for the bounded first route; compile-latency evidence should trigger background compilation only if user feedback is materially harmed.
- [Khronos multisampling](https://docs.vulkan.org/tutorial/latest/10_Multisampling.html), [wgpu attachment resolve](https://docs.rs/wgpu/latest/wgpu/struct.RenderPassColorAttachment.html), [format flags](https://docs.rs/wgpu/latest/wgpu/struct.TextureFormatFeatureFlags.html) and [adapter format capabilities](https://docs.rs/wgpu/latest/wgpu/struct.Adapter.html): intersect color/depth support, use matching pipeline/attachments and resolve into a single-sample texture. Native adapter extras require the optional format feature. The small existing scene/composite path needs no general postprocess or render-graph framework.
- [Unity URP antialiasing](https://docs.unity.com/en-us/engine/6000.0/manual/render-pipelines/universal-render-pipeline/anti-aliasing): MSAA directly addresses triangle silhouettes, with extra sample storage/bandwidth; it does not solve texture/specular aliasing. A composite FXAA alternative would avoid MSAA attachments but add edge-filter work and can soften detail; it is an untested alternative, not an implemented fallback. TAA requires history/motion information and introduces temporal artifacts, beyond this bounded correction. Compare 1×/2×/4× release GPU/CPU cost, memory payload and actual framebuffer edges before retaining the provisional default; no performance superiority follows from the technique choice.
- [Bevy instancing example](https://bevy.org/examples/shaders/custom-shader-instancing/): shared mesh plus instance attributes reduces per-object draw submission. Its custom culling caveat reinforces the need for correct transformed bounds. Ruster groups instances sharing a mesh ID, retains their vertex/index buffers and uses a bounded instance stream, with no speculative general ECS/render graph. This is a fit-for-workload design choice, not evidence that instancing is faster at three objects. Per-object vs instanced before/after timing and representative larger workloads would be needed for an optimization claim.

M6 research was rechecked 2026-11-04 against the linked primary Bevy/wgpu pages and installed wgpu30 source. Bevy batches matching mesh/material handles; Ruster adopts only mesh-ID grouping for its existing single shader. Additional meshes add draw calls and resident data; this is functionality with bounded ownership, not a measured speedup over M5. No engine implementation source was copied. The future application-kit requirements can revisit the ownership boundary when real requirements justify toolkit independence.

## Vulkan SPIR-V compatibility workaround

Ruster vendors a narrowly patched `wgpu-hal30.0.1`: Vulkan shader generation targets SPIR-V1.3 for the current basic graphics/timestamp feature set, and the upstream suppression of VUID10684 is removed. Naga30.0.1 emits explicit layout decorations on function-local structs that are invalid in SPIR-V1.5/1.6; rendering successfully and clean upstream debug logs did not prove validity. This cap produces valid SPIR-V1.3 directly rather than rewriting a binary header or hiding diagnostics. The Vulkan device/API version remains unchanged.

The [vendor provenance and patch record](../../third_party/wgpu-hal/RUSTER-PATCH.md) records upstream issue, exact changes, license/checksum, independent `spirv-val` evidence and limitations. Revisit the cap before requesting modern shader features or upgrading wgpu. Root integration must inspect raw release validation output because Rust test success does not itself fail on Vulkan layer diagnostics.


`viewport_with_navigation` is an additive frontend-controlled variant. `NavigationOptions` carries an optional validated `CameraState`, frame-selected/reset requests, speed and separate pointer/keyboard enable flags. Middle-drag/Shift-right pan, scene Fit and selected bounds use the existing transformed mesh geometry; RMB-held W/A/S/D/Q/E movement runs only with frontend permission and actual focus. The editor disables it for text/modal/gesture ownership and persists camera context independently of scene data. Existing viewport wrappers retain their signatures and GPU ownership; navigation adds no renderer resources. `CameraState::is_valid` checks finite bounded context before restoration. Physical focused navigation and visual lifecycle still require separate native evidence.


`CameraState::orthographic` and `NavigationOptions::{toggle_projection,view_preset}` provide explicit perspective/orthographic and `ViewPreset` axis/isometric/free views. Orthographic projection keeps GPU clip depth0..1 and overlay clip depth−1..1 with matched screen x/y; the gizmo toolkit unprojects those near/far endpoints without an additional orthographic mode flag. Top/bottom views use a nonparallel up vector. Framing updates bounds while retaining projection/orientation, while Reset restores the free scene view. Preferences serialize this camera choice only in the editor layer. Unit tests exercise every preset, depth endpoints, picking/alignment and real gizmo gestures under both projections; this does not replace native GPU/physical-input acceptance.


## V2a authored diffuse packet — implementation checkpoint2026-11-05

The shared viewport consumes Scene7 `lighting` separately from geometry. Legacy uses the preserved fixed0.28ambient/0.72directional branch; authored mode sums scene ambient, one directional and up to four point lights. Explicit authored zero lights/zero ambient stays dark. Relative linear RGB/intensity, finite range and soft near attenuation are defined in [0031](../../docs/decisions/0031-authored-diffuse-lighting.md); this is diffuse SDR without exposure/HDR or a photometric claim; the V2b section adds optional Sun occlusion. Directional rotation follows local−Z emission; only point translation affects its illumination. Geometry rendering/picking/Fit still uses Scene.objects; editor light overlays are separate authoring work.

One retained192byte uniform/bind group at **group2/binding0** is additive to camera group0 and opaque material group1. Its16byte fields are mode/enabled-point/enabled-directional/reserved u32, premultiplied ambient RGB/reserved, incoming direction/reserved and premultiplied directional RGB/reserved, followed by four32byte point records (position/inverse-range-squared and premultiplied RGB/reserved). RGB already includes relative intensity; reserved lanes are zero. Existing vertex locations0–11 retain their meanings; built-in vertex output adds world-position varying4. `Metrics` exposes `lighting_bytes`, cumulative `lighting_uploads` and `lighting_upload_bytes`: initial Legacy payload counts once, identical packets write nothing. Light property edits do not rebuild meshes/textures or compile a shader. Invalid unvalidated public viewport lighting is diagnosed and rendered safe authored-dark rather than falling back to a hidden sun. CPU preparation sampling includes bounded light packet preparation; first ten scene frames remain warmup.

Custom WGSL may compile without using group2 and therefore retain its own lighting/appearance. Binding compatibility does not certify authored-light semantics. Incompatible candidates preserve the active last-good pipeline; hosts must describe that active shader truthfully. Existing custom-shader export restrictions remain. The owning opt-in Vulkan case now includes24lighting readback/counter cases, legacy equivalence, near/range/nonuniform-normal/overlap/max-light boundaries and old-custom-shader behavior in addition to prior lifecycle checks. [Current evidence](../../docs/evidence/V2A-foundation.md) distinguishes these technical probes, early exported-resource exhibit appearance and pending editor/native/cost acceptance.


## V2b Sun-shadow integration (in progress)

Scene8 adds optional bounded Sun shadows to the built-in authored-lighting path. A separate retained depth pipeline uses existing mesh/instance buffers and upload-identity local bounds. Camera-independent world coverage includes every displayed opaque geometry group, including runtime/transient transforms; the initial implementation redraws depth each enabled callback. Standard1024 and High2048 use one single-sampled Depth32Float map with fixed3×3 nearest comparison and receiver-plane correction. Default numerical bias is0.15world-texels, normal offset0; the coverage fit and cost/creator acceptance remain under [V2b](../../docs/plans/V2B-SUN-SHADOWS.md).

New group3 preserves groups0..2 and the vertex ABI. Successful custom WGSL owns appearance and disables built-in shadow generation; restoring the exact built-in source restores that contract. Compilation failure preserves the last-good pipeline/appearance flag. A second callback in one frame is rejected before shared writes and does not composite another viewport's target. This remains one viewport per renderer.

Full-size depth payload is4MiB at1024 and16MiB at2048. One active and one retiring map are permitted; replacement waits if the retirement slot is occupied. Submitted-work completion publishes a flag and repaint, and the owner releases completed bundles on a later callback. Disabled rendering immediately binds a neutral map/skips depth; pending disposal can retain bounded maps until genuine progress. Separate permanent compatibility payload is4bytes neutral depth plus80bytes uniform. These payload counts exclude driver/binding/pipeline overhead and do not establish total VRAM peaks.

Working-tree integration is not complete creator/native/standalone acceptance. [Feasibility evidence](../../docs/evidence/V2B-feasibility.md) records checks, failures and remaining gates.


`shadow_observation(RenderState)` copies only bounded scalars from the latest prepared callback, with separate requested/applied map size and retained/retiring payload. It returns None before any prepared frame. It may describe an earlier authored/runtime view and does not assert GPU completion; frontend commands must not promote it to proof that a hidden edit painted. Additional timestamp scratch is32bytes above V2a (two32byte rather than16byte buffers), plus two implementation-sized query slots; compatibility84bytes names only neutral depth/uniform.


Rapid High disable/re-enable before retirement completion can retain two16MiB maps (32MiB logical overlap); Standard/High replacement alone retains20MiB. Actual lifecycle evidence covers both and final drain. The scalar report separates numerical precision limitation from ordinary coverage/detail limits and reports cumulative encoded depth/map-allocation/80byte-uniform upload counts. Uniform creation counts once; unchanged packets skip writes. Extra bounded shadow/color sample payload is about96KiB at4096samples on x86_64, and cached bounds add24bytes per retained mesh. These are payload accounting, not complete process/driver memory measurements.


## V3a opt-in surface feasibility — 2026-11-06

This is implementation awaiting the [Surface Study](../../docs/plans/V3A-SURFACE-STUDY.md) quality/cost and creator gate, not accepted complete PBR. `LegacySdr` remains the omitted scene display profile: its scene shader, Rgba8UnormSrgb attachment and composite transfer arithmetic retain the accepted path. Materials retain `LegacyDiffuse` by omission. No existing scene or material is automatically converted.

Explicit `SurfaceHdr { exposure_stops }` selects a fixed Rgba16Float linear scene target plus the existing single composite draw. It supports the opt-in `Dielectric { roughness }` material: perceptual roughness0.08..1 (proposed minimum pending moving-highlight quality), alpha=r², GGX distribution, height-correlated Smith visibility, Schlick Fresnel with fixed F0=.04 and energy-shared Lambert diffuse. Existing relative Sun/point intensity/range remain; Sun shadows multiply all direct Sun energy, including specular. Artistic ambient is diffuse fill with .96 energy share for dielectric surfaces, not an environment/reflection source. There are no tangents, normal maps, metallic response or environment lighting. LegacyDiffuse in the HDR profile retains relative diffuse lighting without the old output clamp. Dielectric authored fields are inactive under LegacySdr/custom shaders.

Camera group0 keeps its64byte view-projection prefix and appends a16byte eye/mode vector, visible in vertex/fragment stages. Perspective packs eye position/w1; orthographic packs direction toward the camera/w0. Existing material/lighting/shadow groups and locations0..11 keep their offsets; instance location12 appends one16byte response/roughness vector (160byte total stride). Custom shaders still receive only declared attributes. Inverse-transpose normal and existing displayed model matrices include positive nonuniform, transient and runtime transforms.

Display exposure is manual−8..8stops, default0. The fixed Khronos PBR Neutral function maps nonnegative linear Rec.709 to linear SDR before the existing output convention applies transfer exactly once: hardware for sRGB output attachments, explicit sRGB transfer for gamma attachments. It does not enable HDR monitor output. Egui/gizmo overlays remain after composite, outside scene exposure. Source inspected2026-11-06: [Khronos implementation at180b1a7](https://github.com/KhronosGroup/ToneMapping/blob/180b1a7bddec33f73fe41712a2963cc3ad8e5547/PBR_Neutral/pbrNeutral.glsl), [specification](https://github.com/KhronosGroup/ToneMapping/blob/180b1a7bddec33f73fe41712a2963cc3ad8e5547/PBR_Neutral/README.md). The WGSL translation is marked modified and retains upstream2024Khronos attribution; upstream `.reuse/dep5` assigns Apache2.0 to the GLSL implementation. The [license](src/PBR_NEUTRAL_LICENSE.txt) is retained. Root must include that license/attribution in exported application notices before V3a delivery.

Installation retains two fixed built-in scene pipelines when HDR is supported, plus at most one accepted custom scene pipeline. Roughness/exposure/profile edits never compile pipelines. Accepted custom WGSL uses its original SDR target/pipeline regardless of preserved authored HDR settings; `DisplayStatus::CustomShader` and requested/applied scalars expose their inactivity. Failed compilation retains the active pipeline and appearance flag atomically. Restore builtin reapplies the saved display profile on next prepare.

SDR and HDR negotiate sample counts independently from actual adapter/device format flags. HDR requires renderable/filterable/bindable RGBA16F and renderable depth; unsupported format feedback is explicit `UnsupportedDevice`, with requested HDR/applied SDR kept distinct. A supported profile may negotiate a lower supported sample count, reported as requested versus applied. Target keys include dimensions/format/samples, so pipeline and attachment formats/counts cannot be mixed during profile changes.

Each active target stays within256MiB logical attachment payload. SDR uses8bytes/pixel at1× or4+8×samples; HDR uses12bytes/pixel at1× or8+12×samples. Dimensions scale uniformly to cap/device limits. Ownership is one active bundle plus at most one genuinely prior-submit-fenced retiring bundle (maximum512MiB logical overlap), excluding driver/binding/pipeline allocations and separate shadows. When retirement is full, resize/profile requests coalesce by re-evaluation on the next callback and skip painting until a compatible bundle can be allocated. No target candidate queue or unbounded logical target churn is retained. Submission completion publishes a flag and repaint; subsequent owner callbacks drain retirement. A pending callback does not composite a mismatched or another viewport's target.

`display_observation(RenderState)` reports bounded requested/applied profile, exposure, samples, target dimensions, availability/status and requested/active/retiring payload/allocations. Requested physical dimensions/bytes are kept separate from cap-scaled dimensions, with explicit resolution-limited feedback. `Metrics` exposes the same scalars; these describe prepared state and may be stale, never GPU completion. Existing `gpu_scene_us` remains shadow-through-color and excludes composite/UI; the feasibility comparison must separately measure whole-scene GPU including the display composite.

The existing CPU owning ABI/lighting and target-cap/sample tables now cover surface/display WGSL validation, additive camera/instance offsets, perspective/orthographic vectors and HDR byte accounting. The existing ignored `shader_rejection_preserves_renderable_pipeline` GPU probe adds production dielectric/HDR/exposure, scalar mesh/texture/target reuse, custom restore and both sRGB/gamma output conventions. It remains a bounded numerical/boundary probe, not curved-surface motion, Sun-highlight occlusion, creator usability or performance evidence. No execution results are claimed here; root owns serialized Cargo/GPU checks and the baseline/candidate gate.
