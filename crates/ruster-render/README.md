# Shared 3D viewport

The bounded Rust/wgpu Vulkan renderer is used by the scene editor and this independent binary. Both draw the same scene transforms with the same pipeline; the binary has no editor or MCP dependency. It currently uses eframe for window/device/presentation and UI embedding. This is a shared rendering path, not yet a toolkit-independent application kit.

```sh
cargo run --locked -p ruster-render
cargo run --locked -p ruster-scene -- demo /tmp/ruster-scene.json
cargo run --locked -p ruster-render -- --scene /tmp/ruster-scene.json --ticks 10 --frames 90
cargo run --locked --release -p ruster-render -- --objects 3 --frames 180
cargo run --locked --release -p ruster-render -- --objects 256 --frames 180
```

Use a new filename for `demo`; existing destinations are protected. Use a valid saved scene path for `--scene`. `--objects 256` generates a 16×16 grid of unit-cube instances; `--objects 3` uses the default three-object scene. These options cannot be combined with `--scene`. `--ticks 0..10000` advances the shared static `Preview` lifecycle before rendering: it counts explicit ticks, without application-specific animation. The shutdown summary includes scene fingerprint, revision and tick for comparison with CLI/editor. `--frames 1..10000` repaints and exits after at least that many rendered scene frames. Without it the window sleeps when no redraw is requested.

Left-click selects the nearest visible transformed surface, using inverse-model ray/triangle intersection for imported meshes and ray/box intersection for procedural cubes, including perspective and depth order. Right-drag orbits; wheel zooms; Fit frames the scene bounds. Camera navigation is frontend session state, separate from saved authored object transforms. Selection lightens the selected material. The opaque material currently uses RGB only; stored alpha is reserved and does not enable transparency.

## Embedding and ownership

Call `configure_setup(&mut WgpuSetupCreateNew)` before device creation to request `TIMESTAMP_QUERY` only when supported. Restrict instance backends to `wgpu::Backends::VULKAN` in the host. After creation, call `install(&RenderState)` once; retain the returned `MetricsHandle` if diagnostics are needed. Call `viewport(&mut egui::Ui, &Scene, Option<&str>) -> Option<String>` to paint and receive a newly selected stable ID. Inputs must satisfy `Scene::validate()`.

The current integration supports one viewport per eframe renderer. Camera state is isolated by UI/scene ID. A persistent indexed cube (24 vertices, 36 indices), retained per-asset vertex/index buffers and a geometrically grown instance buffer feed one indexed instanced draw per referenced mesh ID. GPU buffers reuse stable immutable `Arc<Mesh>` snapshots and are replaced after explicit content refresh; unused assets are evicted. The cache enforces 64 meshes, 32768 triangles per mesh and 32 MiB aggregate imported mesh payload, matching AssetStore bounds. It does not silently truncate geometry. Each instance contains its model matrix, inverse-transpose normal matrix and color; fixed-axis rotation applies X then Y then Z. No raw Vulkan or unsafe Rust is used here. wgpu owns device/resource synchronization and eframe owns surface/device lifecycle. Dropping the host drops resource handles; pending timestamp callbacks retain only their readback buffer and diagnostics until completion.

`egui_wgpu::CallbackTrait::prepare` records an offscreen color/depth scene pass into the host encoder. `paint` composites its sampled color into egui's existing pass. The offscreen target is recreated when physical viewport dimensions change, clamped to device limits. It uses `Rgba8UnormSrgb` and `Depth32Float`, single-sample, a perspective look-at camera, backface culling and simple directional diffuse plus ambient lighting. The composite chooses linear/sRGB framebuffer output correctly. This bounded two-pass integration gives the scene a real depth attachment without imposing an egui depth configuration on the host. It costs one color texture, one depth texture, a sample and a composite draw. Multiple views, shadows, PBR, material import and general render graphs are outside this slice.

## Imported geometry and controlled shader refresh

`viewport_with_assets(ui, scene, selected, &BTreeMap<String, Arc<ruster_assets::Mesh>>)` draws stable imported references. Resolve snapshots through `ruster-assets`; keep their Arc identity stable between content operations. Existing `viewport` remains the procedural-only convenience wrapper. Camera Fit computes exact transformed vertex bounds and imported picking tests actual front-facing triangles. Missing references use the cube fallback; the host must display AssetStore/missing-reference diagnostics. The standalone `--scene` path opens its parent as the asset root, reports missing/invalid references, and offers **Refresh assets**, which explicitly re-resolves content and resets its static preview tick to zero. No background file watcher accepts changes.

`default_shader()` exposes the built-in WGSL. `refresh_shader(&RenderState, source)` synchronously builds a candidate pipeline inside a wgpu validation error scope and swaps it only after validation succeeds. Source is bounded to 64 KiB UTF-8. The `vs`/`fs` entrypoints, camera uniform at group0/binding0, vertex/instance attributes, depth/cull/color target and composite pass remain fixed. Malformed WGSL and incompatible resource bindings return an actionable error while retaining the previous usable pipeline. This supports local trusted shader iteration, not arbitrary shader layouts, materials, sandboxed untrusted GPU programs or Rust hot reload. Compilation may block the UI thread; there is no background compiler or general pipeline cache.

The standalone CLI can load a trusted explicit source path initially:

```sh
cargo run --locked -p ruster-render -- --scene examples/arrangement.scene.json --shader /tmp/scene.wgsl --frames 90
```

Copy the built-in [scene.wgsl](src/scene.wgsl) before editing. Initial shader failure is reported and the built-in pipeline still renders. **Refresh scene shader** rereads that explicit path; absent `--shader`, the button reads `scene.wgsl` beside the loaded scene only when clicked. Reads are bounded before compilation. The CLI's explicit shader path is trusted and can be outside the project; the editor enforces its own project-local path policy. Shader state is session-only and does not alter scene revisions or preview snapshots.

CPU regression coverage checks imported surface picking beyond the old cube bounds, empty space inside a mesh bounding box and exact transformed fit bounds. Explicit Vulkan boundary coverage is `cargo test --locked -p ruster-render shader_rejection_preserves_renderable_pipeline -- --ignored`: it accepts a valid replacement, rejects malformed and incompatible-binding candidates, then submits the retained pipeline. This device test complements native resize/shutdown and frontend refresh evidence; it does not prove a visual shader result.

## Diagnostics and measurement

The standalone binary prints adapter/backend on creation and a bounded summary on shutdown, including cumulative mesh buffer creations/upload payload and last-frame scene draw calls. The built-in cube counts as one mesh creation; stable imported snapshots should add one creation each, not one per frame. These counters measure renderer payload operations, not allocator/driver transfers. First ten rendered scene frames are warmup; each CPU/GPU sample vector is capped at 4096. CPU preparation measures model/normal/color instance preparation and mesh grouping plus callback upload/target preparation and command encoding, including new GPU mesh creation on refresh. Stable mesh snapshots avoid repeated vertex/index uploads. It excludes UI layout, picking, presentation waiting and GPU execution. GPU timestamps measure the offscreen scene pass only, including its clear/draw; they exclude UI/composite, presentation, CPU work and readback. They use asynchronous map-on-submit readback with at most one pending sample. Therefore GPU/CPU sample counts can differ. `None` is a missing measurement, never a zero-time GPU claim. If timestamps are unavailable the renderer still runs and reports the gap explicitly.

Memory figures are resource payload estimates, not allocated VRAM: cube vertices+32-bit indices = 720 bytes (M5 used 16-bit indices and 648 bytes); imported vertices+indices = 24 bytes per vertex + 4 bytes per index; instance capacity = 128 bytes × next power-of-two object capacity (minimum one); color/depth = physical width × height × 8 bytes. Camera uniform adds 64 bytes; enabled query resolve/readback adds 32 payload bytes. These omit driver alignment, query storage, pipeline/descriptor bookkeeping, staging, swapchain, egui and process allocations. No allocation-count, total-memory or competitive-performance claim follows from them.

The 3-object and 256-object release commands establish declared initial workloads. Record hardware/driver, window size, validation state, warmup/repeats and compositor visibility when publishing samples. Hidden-workspace rendering is potentially throttled; compare matching conditions. The previous ash schematic cannot be a like-for-like 3D baseline. This implementation establishes a baseline rather than claiming an optimization win. A future cached unchanged-instance upload experiment should compare CPU preparation/upload bytes and end-to-end correctness at both workloads before introducing broader invalidation machinery.

On the local desktop, the initial title `Ruster | Shared 3D` matches the existing workspace-2 rule. Verify routing before interaction; do not switch the user's workspace or use global input. Root integration owns GPU validation, resize/shutdown and visual evidence; compile/unit success alone does not prove Vulkan lifecycle correctness.

## Primary research and tradeoffs

Sources consulted 2026-11-04; APIs also checked against installed egui-wgpu 0.37.0 and wgpu 30.0.1 source:

- [egui-wgpu callback lifecycle](https://docs.rs/egui-wgpu/latest/egui_wgpu/trait.CallbackTrait.html): shared callback resources and prepare-before-paint ordering fit one host-owned device and encoder. The integration deliberately accepts eframe coupling; a separate standalone Vulkan owner would duplicate substantial lifecycle work at this stage.
- [wgpu render-pass attachments and timestamps](https://docs.rs/wgpu/latest/wgpu/struct.RenderPassDescriptor.html) and [map-on-submit](https://docs.rs/wgpu/latest/wgpu/struct.CommandEncoder.html#method.map_buffer_on_submit): explicit color/depth reads/writes and submission-ordered readback avoid CPU blocking. Optional timestamp support is a diagnostic capability, not a rendering requirement.
- [wgpu30 validation error scopes](https://docs.rs/wgpu/30.0.0/wgpu/struct.ErrorScopeGuard.html): pipeline/module creation errors can be collected before publishing a candidate. An explicit shared bind-group/pipeline layout preserves camera binding compatibility across replacements. A controlled synchronous refresh is sufficient for the bounded first route; compile-latency evidence should trigger background compilation only if user feedback is materially harmed.
- [Bevy instancing example](https://bevy.org/examples/shaders/custom-shader-instancing/): shared mesh plus instance attributes reduces per-object draw submission. Its custom culling caveat reinforces the need for correct transformed bounds. Ruster groups instances sharing a mesh ID, retains their vertex/index buffers and uses a bounded instance stream, with no speculative general ECS/render graph. This is a fit-for-workload design choice, not evidence that instancing is faster at three objects. Per-object vs instanced before/after timing and representative larger workloads would be needed for an optimization claim.

M6 research was rechecked 2026-11-04 against the linked primary Bevy/wgpu pages and installed wgpu30 source. Bevy batches matching mesh/material handles; Ruster adopts only mesh-ID grouping for its existing single shader. Additional meshes add draw calls and resident data; this is functionality with bounded ownership, not a measured speedup over M5. No engine implementation source was copied. The future application-kit requirements can revisit the ownership boundary when real requirements justify toolkit independence.

## Vulkan SPIR-V compatibility workaround

Ruster vendors a narrowly patched `wgpu-hal30.0.1`: Vulkan shader generation targets SPIR-V1.3 for the current basic graphics/timestamp feature set, and the upstream suppression of VUID10684 is removed. Naga30.0.1 emits explicit layout decorations on function-local structs that are invalid in SPIR-V1.5/1.6; rendering successfully and clean upstream debug logs did not prove validity. This cap produces valid SPIR-V1.3 directly rather than rewriting a binary header or hiding diagnostics. The Vulkan device/API version remains unchanged.

The [vendor provenance and patch record](../../third_party/wgpu-hal/RUSTER-PATCH.md) records upstream issue, exact changes, license/checksum, independent `spirv-val` evidence and limitations. Revisit the cap before requesting modern shader features or upgrading wgpu. Root integration must inspect raw release validation output because Rust test success does not itself fail on Vulkan layer diagnostics.
