# Owned mesh and texture sources

`ruster-assets` provides two bounded project-local import routes: UTF-8 Wavefront OBJ triangle meshes and opaque sRGB base-color PNG textures. Sources remain ordinary creator-owned files. A stable asset ID identifies a typed entry in `.ruster-assets.json` version2 independently of its filename. Catalog1 remains readable. These asset APIs are foundations for [V1 textured materials](../../docs/decisions/0029-opaque-material-and-texture-ownership.md); their existence does not establish the complete editor/MCP/runtime workflow.

```sh
cargo run --locked -p ruster-assets -- import /path/to/project roof meshes/roof.obj
cargo run --locked -p ruster-assets -- import /path/to/project paint textures/paint.png
cargo run --locked -p ruster-assets -- inspect /path/to/project
cargo run --locked -p ruster-assets -- refresh /path/to/project paint
cargo run --locked -p ruster-assets -- rename /path/to/project paint textures/paint-renamed.png
```

Create source directories yourself. Import infers Mesh/Texture from the case-sensitive `.obj`/`.png` extension. `rename` physically moves a source, preserves its ID/kind/accepted hash, and refuses an existing destination or a kind-changing extension. Each normalized relative source path has one stable asset ID. Import/rename persist the catalog immediately; scene save/Undo is a separate transaction. There is no file watcher or automatic acceptance of changed source bytes.

## OBJ and UV policy

Accepted records: `v x y z`; optional `vt` with1–3 coordinates and `vn` with3; triangle `f` records using positive or relative negative indices, including `v/vt`, `v//vn` and `v/vt/vn`; comments and `o`, `g`, `s` metadata. Indices must refer to already declared data. Generated flat face normals retain the previous import semantics. Imported normals, smoothing and names do not affect geometry. Triangulate and disable material export in the source tool: `mtllib`, `usemtl`, quads, curves, unsupported directives, zero/out-of-range indices, non-finite coordinates and degenerate triangles produce line-numbered errors. Coordinates are bounded to±1,000,000.

Complete UVs are retained by expanded face corner, including seams and negative indices, as `Mesh.texcoords: Option<Vec<[f32;2]>>`. The stream has exactly one entry per vertex when present. `vt u` defaults its second component to0; a third component is validated and ignored for this2D route. Raw repeat coordinates are retained and no V flip occurs in the importer. The renderer must flip V exactly once for the top-row-first image convention. Meshes missing any corner UV remain valid geometry with no complete stream; `has_complete_uvs()` and `uv_diagnostic()` expose that limitation. Textured dependency validation belongs to the consuming scene/runtime workflow.

OBJ source size is at most1MiB; source positions/UVs/normals each at most98,304; triangles at most32,768. Derived geometry emits an independent vertex per corner, at most98,304 vertices and indices. `Mesh::payload_bytes()` counts actual position/normal/index/UV logical bytes. The project mesh payload cap is48MiB, increased from32MiB so recovering UV attributes does not reject previously supported geometry sets merely for those attributes. Container overhead and caller-retained snapshots are excluded; this is a compatibility bound, not a measured performance budget.

## PNG, color and mip policy

`decode_png` accepts nonanimated, noninterlaced8-bit RGB/RGBA PNG with standard compression/filtering, at most8MiB encoded and2048 pixels on either edge. Normalized output is tightly packed, top-row-first RGBA8 with alpha255. RGB at source alpha0 is preserved, never premultiplied. Image alpha, including RGB transparency metadata, does not affect this opaque route.

Base-color bytes are interpreted as sRGB. Untagged input, sRGB intent0–3, conventional matching gAMA45455 and sRGB cHRM coordinates are accepted. Conflicting gamma/chromaticity values, ICC/cICP/HDR profiles, grayscale/palette/sixteen-bit/interlaced images and APNG chunks reject explicitly. This fixed policy does not implement general color management. A full chunk preflight checks CRCs, bounded lengths, required header/end, contiguous image chunks and absence of trailing data, including forbidden metadata after image data. The pinned png decoder additionally validates image structure/decompression. Text metadata is ignored.

`Texture { width, height, mips }` contains the complete chain through1×1. Each `TextureMip { width, height, rgba }` stores opaque sRGB RGBA8. Mips average RGB in linear light and encode back to sRGB, with area coverage retaining odd final rows/columns. For example an equal black/white average encodes188, not128. `validate_texture` checks dimensions, complete mip shapes, exact byte counts and opacity. `Texture::payload_bytes()` sums retained mip bytes. The limits are24MiB per complete chain and64MiB across accepted project textures; at most64 combined mesh/texture records are supported. These are selected initial bounds, not measured resource-budget passes. Decoder internal allocation is separately limited to32MiB on its documented best-effort basis; source/output/mip arithmetic is checked independently. Candidate buffers, older Arc snapshots, container overhead and GPU resources can raise peak usage above retained logical payload.

## Catalog, caches and recovery

Asset IDs contain1–128 ASCII letters, digits, `_`, `-`, `.`. Source paths are relative, at most256 bytes, without traversal, reserved `.ruster-` components or symlinks. The catalog is bounded to64KiB. Catalog2 records add `kind: "mesh"|"texture"`; kind must match source extension. Catalog1 is decoded using its strict historical shape and is not rewritten on open. A successful catalog-changing mutation writes2. Unsupported versions and new fields under the old label reject. Same-content Refresh can repair status/cache without advancing revision or migrating catalog bytes.

A successful import/refresh hashes exact source bytes with SHA-256 and publishes the derived cache before committing catalog bytes. Mesh cache writes use `.ruster-cache/meshes/v3-HASH.bin`; caches2/1 remain readable, without automatic deletion. The116-byte header retains `RUSTMESH`, little-endian version/counts,64 ASCII source-hash bytes and32 binary checksum bytes. In version3, the vertex-count high bit marks a complete UV stream. The payload has six little-endian `f32` values per vertex, then optional two-float UVs per vertex, then `u32` indices. The checksum covers all header fields except itself plus payload. Counts, exact length, geometry and UV validity are checked before use. Serialized mesh cache size remains bounded to16MiB.

Opening prefers mesh cache3, then2, then1. Old caches lack UV information: when exact accepted source remains available, it is reparsed to recover UVs and publish3 without accepting source edits or rewriting the catalog. Missing sources can retain old geometry without UVs. Cache1 uses strict historical mesh serialization for its checksum, so adding UV support does not invalidate old checksums or permit UV fields under an old label. Absent UVs remain omitted from ordinary Mesh serialization.

Texture cache `.ruster-cache/textures/v1-HASH.bin` stores dimensions, complete opaque mip payload, source identity and a checksum covering semantic header/payload. Size/counts/shapes/checksum/opacity are validated before acceptance. It preserves last-good texture content across reopen when sources change or disappear. Removing caches rebuilds unchanged valid sources. Cache keys contain importer version/source hash, never an asset ID or absolute local path. Do not commit derived data.

Opening reads/hashes each source once. Matching accepted bytes plus a validated current cache skip parsing/decoding; valid legacy mesh caches trigger the UV recovery described above. Changed, missing or malformed sources retain usable accepted caches and report Invalid/Missing diagnostics. Refresh is the explicit acceptance boundary. Failed import/refresh/cache publication/catalog publication preserves previous accepted payload/hash/revision/catalog bytes; an orphan derived cache is disposable. A later valid Refresh recovers. Missing both accepted source bytes and a usable cache is irrecoverable; this crate never replaces failed content with a cube/placeholder.

Rename rolls its file move back if catalog publication fails and reports both paths if rollback also fails. Catalog writes use same-directory temporary files, file sync and atomic replacement; this is not universal power-loss durability or a transaction across scene and catalog files.

## APIs and concurrency

`mesh()`/`texture()` borrow accepted content; `mesh_snapshots()`/`texture_snapshots()` return cheap maps of immutable `Arc` snapshots. `meshes()` preserves the legacy owned-copy API. Identical decoded content preserves Arc identity through source-only edits, unchanged Refresh, unrelated changes, rename and failures. Changed accepted content replaces only that asset's Arc. Consumers should release obsolete snapshots; retained snapshots are outside catalog payload accounting. `inspect()` exposes kind, stable ID, relative source path, accepted hash, Ready/Missing/Invalid status and diagnostics.

Mutations compare expected revision and the complete on-disk catalog baseline under a project advisory lock. `import_at`, `refresh_at` and `rename_at` reject stale revisions; convenience methods use the current revision. Session/draft permission guards belong to hosts. The nonblocking lock reports Busy for explicit retry and explicitly unlocks on drop even with inherited/duplicated descriptors. Reopen after a disk conflict. Regular-file preflight avoids blocking on FIFOs; special-file write destinations reject rather than being replaced. Confinement/symlink checks support trusted project use, not a hostile same-user filesystem race sandbox.

`export_snapshot(&BTreeSet<String>)` captures metadata for selected mesh/texture IDs without filesystem I/O. `ExportSnapshot::read_sources()` returns only exact accepted source bytes, using kind-specific bounds/confinement and checking catalog baseline before/after reading. Changed bytes require Refresh. It does not acquire locks, open another store, write caches or include unselected/history-only sources. The caller must compute the complete object/material/texture dependency closure and preserve kinds in delivery descriptors; this method is not itself an exporter.

## Verification

`cargo test --locked -p ruster-assets` covers supported cache1/2 recovery and cache3 publication, UV seams/negative indices/partial legacy behavior, catalog1 no-write recovery/strict old labels, typed texture last-good refresh/reopen/mixed export, source-only Arc identity, PNG policy/color/mip/cache boundaries, count/payload bounds, failed publication, rename rollback, path/symlink/conflict guards and CLI wiring. Unix CLI child checks exercise FIFOs and actual lock contention without risking a hung runner. Other platforms require their own filesystem evidence. These source checks do not establish GPU, native editor, exported application or resource-performance acceptance. The package inherits the workspace MIT OR Apache-2.0 license and uses the pinned png crate for image decoding.

Unchanged accepted PNG Refresh still checks confined source bytes/hash and repairs the disposable cache, but reuses immutable decoded pixels/mips instead of decoding again. A missing accepted snapshot takes the normal validation path. Cache write failures retain the accepted payload/catalog revision and report a diagnostic; repair and Refresh can clear it. Mesh Refresh continues parsing so old caches can recover UVs. This avoids redundant work; it does not make import/cache operations asynchronous.

Opening a changed PNG marks it Invalid with “Source changed; Refresh to validate and accept” and retains last-good cached content where available. Open does not decode or validate the changed image. Explicit Refresh gives format diagnostics and accepts valid changes. Missing, oversized and unreadable files still report their specific read failures. Mesh-open diagnostics are unchanged.

`ExportSnapshot::source_ids` reads captured metadata only. `read_verified_sources` verifies bounded source buffers one at a time and passes ownership to a consumer; callback failure or final catalog mismatch rejects the entire traversal. Consumers must write disposable staging and publish only after success. `read_sources` remains a collecting compatibility API and can retain the complete encoded closure; the editor uses the visitor.
