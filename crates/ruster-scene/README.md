# Generic authored scenes

This application-neutral scene foundation is independent of logistics, rendering, editor, assets and MCP. Each stable object has an optional stable mesh asset ID (`None` selects the procedural unit cube), translation, Euler rotation (radians, fixed-axis X then Y then Z, world qz*qy*qx), positive scale and linear RGBA color. The initial storage is a bounded vector, chosen for small whole-scene inspection and direct object lookup; this is not a general ECS or a scalability claim.

From the repository root:

```sh
cargo run --locked -p ruster-scene -- demo /tmp/ruster-scene.json
cargo run --locked -p ruster-scene -- inspect /tmp/ruster-scene.json
cargo run --locked -p ruster-scene -- transform /tmp/ruster-scene.json 0 left -3 1 0
cargo run --locked -p ruster-scene -- undo /tmp/ruster-scene.json 1
cargo run --locked -p ruster-scene -- redo /tmp/ruster-scene.json 2
cargo run --locked -p ruster-scene -- mesh /tmp/ruster-scene.json 3 left owned-mesh
cargo run --locked -p ruster-scene -- mesh /tmp/ruster-scene.json 4 left none
cargo run --locked -p ruster-scene -- run /tmp/ruster-scene.json 10
```

Use a new filename for `demo`; existing destinations are protected. `transform FILE REV OBJECT X Y Z [RX RY RZ SX SY SZ]` edits translation alone or the complete transform; omitted rotation/scale are preserved. `mesh FILE REV OBJECT ASSET_ID|none` assigns a mesh or restores the procedural cube. The scene CLI and library validate ID syntax only; registry existence, import and missing-asset diagnostics belong to asset-aware callers. The CLI reserves `none` for restoring the cube; the library can represent the syntactically valid asset ID `none` as `Some("none".into())`. `inspect` reports the loaded format version and the next-save upgrade when opening v1. `run` observes a static configurator snapshot for 0..10000 ticks and emits its scene identity, revision, tick, object count and fingerprint. It does not invent physics or application rules. `Preview::new` snapshots authored data; edits do not enter that snapshot until explicit `reset`. Headless and rendered previews can share this lifecycle.

`Scene::validate/load/save` support code-first values. `Session::new/open`, `scene`, `edit(expected_revision, object_id, &transform)`, `set_mesh(expected_revision, object_id, Option<String>)`, `undo(expected_revision)`, `redo(expected_revision)` and `save(path)` provide the authoring boundary. A no-op transform or mesh assignment keeps the revision/history and redo entries. Transform and mesh edits share one chronological undo/redo history. Every successful change, undo or redo increases the revision; stale, invalid and overflowed commands preserve state. `Scene::fingerprint` is a deterministic 16-character noncryptographic FNV-1a checksum of canonical JSON bytes (including revision), for preview comparisons rather than security. Read-only `path`, `is_dirty`, `loaded_format_version`, `undo_len` and `redo_len` expose authoring state. New sessions are unsaved. Save to an opened canonical path checks the full saved document; other paths must not exist. A failed save preserves the file association, history and dirty baseline.

The JSON envelope is `{ "format": "ruster-scene", "format_version": 2, "scene": { "id": "...", "revision": 0, "objects": [...] }, "undo": [], "redo": [] }`. New saves always emit scene v2. Object `mesh` is optional and omitted when `None`, preserving the canonical scene bytes/fingerprints of v1 cube-only scenes. V2 history entries are tagged `{"kind":"transform","id":"...","before":{...},"after":{...}}` or `{"kind":"mesh","id":"...","before":null,"after":"owned-mesh"}`. Scene v1 is decoded through its exact old schema: any object `mesh` field (even null) or tagged history is rejected under a v1 label. Valid v1 transform undo/redo entries migrate intact in memory and are saved as tagged v2 entries. Opening alone does not rewrite the file or mark the session dirty; even saving an unchanged v1 document explicitly upgrades it to v2 without increasing its authored revision. `loaded_format_version()` is 1 after opening v1 and 2 after a successful save (also 2 for new sessions). Failed saves retain this version indicator. Logistics v1 scenarios remain separate and unchanged; opening them as a generic scene fails explicitly without migration. Unknown fields, unsupported versions, inconsistent history and corrupt/truncated inputs fail. Limits are 256 objects, 32 total undo/redo transform or mesh deltas and 1 MiB serialized input/output. IDs use 1..128 ASCII letters/digits/`-_.`; object IDs are unique. Translation and rotation magnitudes are at most 10000 (rotation in radians), scale is 0.001..1000, and colors are finite 0..1. Empty scenes are valid.

Persistence flushes and syncs a sibling temporary file before atomic replacement. `Session` uses nonblocking sibling `.FILE.ruster-lock` advisory locks for cooperating writers, resolves parent aliases, rejects destination symlinks and checks full saved baselines (including same-revision changes). Lock files remain in place. Direct `Scene::save` replaces the file with empty history and requires caller-managed concurrency. Advisory locking does not exclude hostile/noncooperating writers; atomic replacement is not a universal power-loss durability guarantee. The bounded scene format stores mesh IDs rather than source paths or derived mesh payloads. It has no hierarchy, application components or implicit logistics conversion. Asset resolution is deliberately outside this crate.
