# Provisional generic Lua behavior backend

This library is the first generic `lua54` host API1 candidate. It does not select a permanent language, replace the Rhai/Motion Lab experiment, add an editor/scheduler/MCP/DAP service or establish C# suitability. Generic scene format5 remains language-neutral: unknown backends and invalid code are saveable in `ruster-scene`, while this runtime reports structured rejection. There is no mandatory application dependency on an interpreter.

The optional headless consumer uses the same saved document:

```sh
cargo run --locked -p ruster-behavior -- check /tmp/my-scene.json
cargo run --locked -p ruster-behavior -- run /tmp/my-scene.json 8 0.25
```

Use [scene source/binding commands](../ruster-scene/README.md#headless-source-and-binding-edits) to author a project. `check` performs Reset's compile/module/update validation at dt0; `run` then executes0..10000 atomic fixed steps, with optional dt in(0,1] (default1/60). Successful output contains runtime scene/tick/fingerprint JSON; failures exit nonzero with structured diagnostic JSON on stderr, including source ID/hash, binding/object, phase and line where available. Authored project bytes are never changed by either command. Disabled bindings are skipped; unattached unfinished sources remain data. `Diagnostic` also implements standard Error/Display and serialization for Rust consumers. This CLI has no renderer/editor dependency; it is separate from the geometry-only scene preview command.

`Engine::new(Limits)` owns one non-Send Lua VM and a bounded cache of compiled source mains. `reset(&Scene, &Authoring)` validates authored structure and every enabled binding, compiles text-only sources and evaluates each fresh module/update at dt0 against the authored snapshot. Reset discards those trial transforms/time and returns an original-scene `Runtime` only if all enabled bindings succeed. A rejected Reset leaves any previous Runtime under caller ownership. Disabled unfinished bindings are skipped. Applying source/property changes requires explicit Reset; runtime authoring is an immutable copy and runtime transforms never enter authored data.

`step(&mut Runtime)` uses the engine's fixed dt, stable binding-ID order and one immutable tick-start scene. Each binding receives copied input/property/reference data, returning only its owner's complete transform. The host stages every result and commits transforms/tick only after all succeed. Failure preserves all objects and tick. No mutable script globals/upvalues persist between evaluations: cached mains get a fresh allowlisted environment and create a fresh module/update closure each call; their environment is cleared after success/error. The complete evaluation and transform extraction run inside `lua.scope`; the resolver borrows the snapshot and its callback expires/drops Rust captures synchronously, including when Lua leaves unreachable cycles awaiting GC. Memory errors discard a main if cleanup cannot allocate, and explicit GC follows dropped error-path handles so repaired retries can proceed. The cache keeps at most one revision per source and clears older cached entries at its configured capacity; older Runtime snapshots can recompile their own source if needed.

A source must return `{ update = function(transform, props, dt, host) return transform end }`. A transform contains `translation`, `rotation` and `scale` tables, each with exactly the numeric indices1..3. Output components must be finite and satisfy `ruster-scene::Transform::validate`, including translation/rotation ±10000 and positive bounded scale; only validated f32 transforms commit. Rotation is the scene's fixed-axis Euler radians contract. Number/Bool/Text properties become Lua numbers/booleans/strings, Vec3 becomes a1-based table, ObjectRef/AssetRef become stable-ID strings and null references become nil. Asset IDs grant no asset/file access. `host.resolve(id)` returns a fresh copied transform from the same tick-start snapshot, or nil for an absent/null ID. The [follower template](templates/follower.lua) uses Number `speed`, Bool `enabled` and ObjectRef `target`.

The environment exposes a fresh `math` table with `min/max/abs/sqrt/sin/cos/floor/ceil`. It has no global fallback or IO/OS/debug/package/loaders/random/pcall/coroutine/metatable APIs. Lua's lexical `_ENV` refers only to that fresh environment. The host passes its fresh resolve table explicitly to update. This is logical transaction/capability isolation, **not** VM heap rollback, a hard wall-time sandbox or a total-process-memory guarantee. Host conversion/callback work is bounded by scene/property bounds but is outside Lua instruction accounting.

Working defaults are dt1/60,20,000 instructions per binding across module+update,1,000,000 per complete Reset/Step, hooks every100 instructions,16MiB VM allocator limit and256 cached sources. All are provisional agent-selected bounds. Limit validation requires dt in(0,1], VM64KiB..64MiB, cache1..256, binding instructions1..10million, tick instructions1..100million and a positive hook interval no larger than either instruction budget. Hooks approximate instruction accounting at that interval; compilation is bounded by source size and VM memory, not instruction hooks. Source text, authored/runtime copies, Rust callback/cache metadata and allocator overhead are outside the VM allocator measurement.

`cancellation()` returns an `Arc<AtomicBool>` that another thread may set. `Engine::with_cancellation(limits, token)` accepts an existing shared token, preserving an already-set cancellation request during VM construction; `Engine::new` retains its independent default token. An owning worker can therefore cancel before VM setup without waiting for a Ready handshake. Hooks interrupt Lua execution, module boundaries check it and a final pre-commit check protects short last bindings; cancellation stays set until the caller explicitly clears it. No Lua handle crosses threads, and this crate creates no worker/scheduler. Diagnostics carry bounded messages (at most2048 UTF-8 bytes), optional source line, binding/object/source identity, SHA-256 source version, phase and code. No arbitrary evaluation/debugger access is exposed.

mlua0.12.2 is pinned and uses bundled Lua5.4 through `lua54+vendored`, without `send` or DEBUG. [Dependency provenance and narrow safe local-accessor patch](../../third_party/mlua/RUSTER-PATCH.md) record its existing unsafe/FFI boundary; this crate forbids unsafe. The earlier tooling/debugger trial used system Lua5.4.9 and is separate evidence. The resolved lock uses `mlua-sys0.13.0` and `lua-src551.0.2`; its Lua54 branch selects bundled `lua-5.4.9` (headers define release9), corroborated by the actual runtime `_VERSION == "Lua 5.4"` assertion. Package551 is not a claim that Lua5.5 is selected. Six library tests and strict Clippy passed on this Linux host; no sanitizer, Miri, cross-platform or shipped-application evidence is implied.
