# Rusterize ChatGPT workflow — user product direction

Akil clarified that ChatGPT browser-control manipulation of Rusterize is NOT an intended authoring workflow. The browser-control Move/verify/Undo journey demonstrated technical feasibility only, not acceptance of the intended product workflow.

Required intended architecture:
- Prompts produce structured Rusterize MCP tool calls for authoring.
- The localhost dashboard inside ChatGPT is primarily visual feedback, inspection/status and appropriate human controls, not a model-operated click interface.
- Hermes MCP authoring remains a required client path alongside ChatGPT desktop MCP.

Rationale: Akil reports that current-model browser manipulation wastes substantially more usage than direct MCP calls. This is a user-reported experience/product preference, not a measured comparative benchmark in this project.

Do not promote browser automation as an alternative acceptance path for MCP. Actual ChatGPT desktop MCP registration, intended project/owner consent, tool execution and synchronized dashboard feedback remain unqualified. Preserve existing safety/grant distinctions.
