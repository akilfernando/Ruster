# M9 Godot editor reference capture

2026-11-05. This is a visual reference, not an adoption of Godot branding or a claim of creator familiarity. The [unaltered capture](m9-godot-inspector.png) is from the third-party Godot editor, version `4.7.2.stable.arch_linux.ed1daf0bf`, using its OpenGL 3.3 Compatibility renderer on the local NVIDIA RTX 4060 Laptop GPU. It is not a rendering performance comparison, native Ruster evidence or a human usability study.

The disposable scene contained a selected `MeshInstance3D`. In this 1500×1000 capture, the editor presents a scene hierarchy on the left, a large central 3D viewport with local toolbar and selection handles, a file panel below the hierarchy, and a vertically scrolling Inspector on the right. The inspector shows the selected name, property filter, compact type headings and collapsible groups, with property names and values aligned in rows. Resource references have previews and adjacent actions. Some property names are truncated at this inspector width, so the capture also demonstrates a density/readability tradeoff rather than an unqualified target.

The `Node3D` heading is near the bottom and the `Transform` section begins below it; this capture does **not** show Transform first or establish the behavior of its expanded fields. A documentation icon appears beside the selected-object area, but this single image does not demonstrate the help content or interaction. Godot's section hierarchy, grouping and placement are reference observations. Any Ruster decisions should be evaluated against its creator workflow and constraints, not copied as a visual skin.

Root launched `/usr/bin/godot --path /tmp/ruster-m9-godot-reference --editor res://scenes/reference.tscn` under an isolated temporary Godot-specific workspace-2 rule. A disposable `@tool` editor plugin selected the cube, captured the editor base-control viewport after frames and exited normally. The root's process record reports exit 0, active workspace 1, rule cleanup and byte-equal Hyprland configuration SHA-256 `cdebbde78d7c9a3d30e7f2f5e3e4ed72923369dd747214f266c35c649e9d67a6`; the existing user Ruster process was not touched. The capture plugin passed a headless Godot syntax check before the graphical run. No global input, clipboard change or workspace switch was used.

The [bounded archive](m9-godot-reference-capture.tar.gz), SHA-256 `ca6e5f7d7ac54ac8692a3cb6b133a75ad89c80027d1f3e061dfc20282789c1d4`, contains only the disposable project, scene, capture plugin, unaltered PNG, native log and launch/exit records. It excludes the `.godot` cache and saved Hyprland configuration. The native log records the actual OpenGL device and `CAPTURE_OK`; visual properties are observations from the image, not inferred interaction tests.
