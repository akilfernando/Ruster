# M8 generic object construction native journey — 2026-11-04

An independent native journey used a debug build (`cargo build --locked -p ruster-editor -p ruster-mcp --features ruster-editor/inspection`, 16.03 s) on Hyprland/Wayland and the NVIDIA GeForce RTX 4060 Laptop GPU. A disposable copy of the content scene was the starting document. The exact `org.ruster.editor` / `Ruster Editor` window was observed on workspace 2 before interaction, while workspace 1 remained active. A temporary editor-class `render_unfocused` rule enabled background rendering, so this is not performance evidence. The loopback inspection interface sent app-scoped widget events; no global input or clipboard was used.

- **New scene** produced a fresh empty `untitled` scene and new session identity. **Create cube** produced `object-1`; **Rename object** changed its display name to `Beacon` without changing its stable ID. **Duplicate** created `object-2` with the same name. Editing and applying its X position to 2.5 changed that object. **Delete**, followed by **Undo authored edit**, restored the same object and transform.
- While the transform field had an unapplied draft, a real MCP `scene_delete` was rejected with `drafts_pending`. A real `scene_create` then returned a complete created-object diff; repeating its original revision was rejected as stale. An invalid whitespace-padded rename was rejected without changing scene or revision; MCP Undo removed the created object. This used the official Python MCP SDK 2.3.0 over the actual stdio adapter and opt-in private editor socket, not a mock.
- **Save scene** to a new path and **Open scene…** in the editor restored both objects, their IDs, names and transforms with a fresh session identity and clean state. A command using the old session identity was rejected. This is an in-process reopen of the persisted file, not a second editor process. [Inspection evidence](m8-objects-journey.json) redacts transient session tokens; [journey output](m8-objects-journey.txt) records its assertions.
