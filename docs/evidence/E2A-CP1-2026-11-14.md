## Implemented contract

- Default-off listener with local Host `connect_adapter`, `pending_adapter`, `approve_adapter`, `disconnect_adapter`, `connection_state` and local retained-receipt APIs. No MCP command can approve itself. Legacy `RUSTER_MCP_ENABLE=1` creates only an **unbound** listener, not a bypass or production onboarding flow.
- Immutable unpredictable editor incarnation, project authority generation and connection identity; a separately generated256-bit capability stays only in adapter/editor memory. The nonsecret private locator contains identity/pins, never the capability. No capability in persistent Hermes configuration, arguments, logs, scene/history or recovery. Revision/session tokens remain concurrency guards.
- Matched wire `ruster-owner-1`, one fixed locator and one persistent adapter-owner Unix socket. Unbound MCP initialize/tools/list do not open/consume editor authority or disclose project data. First project access creates a pending principal; exact local owner approval is required. No per-call discovery/reselection, active-editor fallback, automatic retry or restart reclaim.
- Locator/file/private-directory/socket identities, symlink components and connected Linux peer credentials are checked. Admission, dispatch and final authorization share the same endpoint/authority checks. Replaced paths fail closed and cleanup never recursively deletes a replacement. This protects cooperating same-UID mistakes and other users, **not hostile unrestricted same-UID code**.
- Revocation on New/Open/Restore initiation, including cancellation/failure, disconnect, owner EOF/restart and editor restart. Legacy scenario New/Open/duplicate/close and its dialog initiation use the same gate. A Save that establishes/changes the asset root also advances project authority and revokes; its new generation entropy is reserved before publication. Destination grants never implicitly transfer.
- One authority lock orders revocation against final authorization. Queued/preparing leases cancel; an authorized CommitLease retains old-owner acknowledgment, adoption, cleanup and terminal receipt after timeout/revocation. Replacement waits old asset/export ownership. Export's final publication uses this same gate and retains its permit through actual cleanup/worker exit. Unknown outcomes never auto-replay.
- Stop/wakeup, bounded incremental socket reads/total writes, owned listener JoinHandle and nonblocking poll/join/drain. Queued requests are canceled explicitly; preparing work remains draining until its cleanup owner releases it. Normal retirement joins without a helper thread. Abnormal owner destruction transfers the actual JoinHandle to one finite asynchronous join job rather than blocking the caller or detaching the listener; this is not a discovery daemon, recurring worker or queue.
- Local retention is at most8 terminal responses, each below65,536bytes; oversized responses leave an explicit bounded diagnostic. No unauthenticated receipt exception exists. This is bounded in-memory continuity, not crash-durable receipts or guaranteed attribution after arbitrary later requests.

The20ms poll/write and2second framing/preparation limits are **selected engineering limits**, not measured scheduler/UI latency guarantees. Scene18/content14/Recovery15/Descriptor5 remain unchanged. Safe peer credentials use an already-locked `rustix0.38.44` direct dependency with net/process features; no package version or system installation is changed.
