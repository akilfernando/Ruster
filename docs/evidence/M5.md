Date: 2026-11-04. Complete within the documented local Linux procedural-scene scope. Architecture and application briefs are in [decision0006](../decisions/0006-scene-and-shared-3d.md) and [M5 briefs](../M5-BRIEFS.md).

## Declared scope and workloads

Generic bounded scene/session/Preview and one procedural cube/color renderer used by standalone and scene editor. Neutral crates have no dependency on logistics, editor or MCP. Existing logistics-v1 tools remain unchanged; the generic envelope is separately identified ruster-scene version1. Static Preview counts ticks and snapshots/reset; no physics/gameplay claim. Headless CLI/editor/MCP operate on the same scene command semantics.

For the initial GPU/CPU baseline use default3 cubes and a16×16 grid of256 cubes, fixed compositor-provided viewport on DP-3, ten rendered-frame warmup and180 frames per run, three release repeats per workload. Record actual viewport payload bytes, not nominal requested window size. Use same background-rendering rule/validation-off conditions for all performance samples. Initial diagnostic sub-budgets (agent-selected experiment targets): p95 CPU preparation<=1ms, p95 scene GPU pass<=4ms at256 objects on this workstation. These are scene-pass targets, not an end-to-end60Hz guarantee or production hardware floor.

Metrics cover CPU instance preparation/upload/encoding and timestamped offscreen GPU scene pass. They exclude full UI/frame/presentation and use resource payload estimates rather than allocated VRAM/process memory. No optimization comparison: the legacy clear-rectangle schematic is not an equivalent3D workload. The new implementation establishes a baseline. Future upload caching needs matched before/after samples and correctness checks.

## M6 audit correction — 2026-11-04

The earlier final release-validation claim above was incorrect. During M6, case-insensitive inspection of the retained `/tmp/ruster-m5-evidence/runtime-final-validation.log` found VUID-StandaloneSpirv-None-10684 messages. The old root check searched only uppercase ERROR and missed mixed-case Validation Error; this is a verification defect, not a clean pass. Debug evidence is also insufficient for this specific VUID because upstream wgpu-hal30.0.1 intentionally filtered that message in its debug callback. Other recorded source tests, native UI journeys, timing samples and preview equivalence remain the evidence they state; they do not cancel the validation failure.

M6 investigation identified the upstream Naga/wgpu SPIR-V layout issue and is validating a bounded dependency correction. The M6 evidence/decision records the repair, raw recapture and improved scanner. Treat original M5 release-Vulkan acceptance as superseded by that corrected evidence, not as proof that the unpatched implementation was error-free.
