## Implementation

A bounded `ruster-application` version1 descriptor identifies title, Scene5 resource, mesh paths and tick duration. ResourceRoot performs bounded confined read-only loading. Shared scene ID validation avoids placeholder object/scene allocation. The existing Motion executable supports explicit creation mode and executable-relative discovery, with visible failure for present invalid descriptors and preserved explicit generic/legacy modes. Creation presentation uses its own title and normal lifecycle controls; native startup validates Reset at dt0 before running. This presentation has source/component evidence, not a new native framebuffer or human-UX pass.

Accepted-source export captures selected catalog metadata without I/O, then a worker reads matching confined OBJ bytes against the exact catalog baseline before/after. No store reopening, project locking, cache writing or silent acceptance of changed sources occurs. A single integrated boundary case checks selected-only capture, no bytes/mtime changes, held-lock reads, source Refresh and same-revision external catalog conflict. A descriptor case checks supported roundtrip/path/version/timestep/duplicate-ID/unknown-field boundaries. Two CLI cases check mode conflicts and executable-relative selection. Existing scene/parser/VM tests are reused.

The app crate directly declares serde/serde_json already in its dependency closure. `cargo metadata --offline --format-version 1` updated only those two dependency edges in Cargo.lock; no locked package/version changed. There is no new renderer, VM implementation, runtime thread or per-paint file scan.
