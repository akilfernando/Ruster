# M8 viewport antialiasing correction

2026-11-04. Actual Unity-user walkthrough feedback identified aliased cube edges. This bounded correction adds hardware MSAA to the existing shared scene/composite path. The 4× default and 256 MiB retained attachment payload cap are agent-selected engineering choices, not user-selected quality settings. This workstation's evidence supports retaining the initial 4× default; other hardware, higher-resolution quality/cost, temporal stability and human acceptance remain unverified.

## Implementation and rationale

The scene pass uses matching-sample `Rgba8UnormSrgb` color and `Depth32Float` depth attachments. At more than one sample it resolves automatically into the original single-sample color texture for the existing composite pass; MSAA color/depth are discarded after the pass. At 1× there is no extra color image or resolve. Pipeline refresh carries the installed sample count, so rejected candidates retain a compatible renderable pipeline. Resize recreates matching attachments; wgpu retains resources needed by pending submissions. No shader ABI, material change, dependencies, unsafe code or general postprocess/render-graph framework was added.

`RUSTER_MSAA_SAMPLES=1|2|4` requests a developer comparison setting in either frontend. The renderer chooses the highest supported count no greater than requested, intersecting color/depth support and requiring color resolve support. Optional native adapter format features are requested only where supported; without that enabled device feature the adapter flags also intersect WebGPU's guaranteed format flags. This matters because guaranteed support includes 4× for these formats, but not 2×. Requested/effective counts are logged, including explicit invalid-value fallback.

Retained attachment payload is 8 bytes/pixel at 1× and `4 + 8 × samples` at higher counts: 20 at 2×, 36 at 4×. The 256 MiB payload cap and device dimension limit uniformly reduce physical dimensions when necessary. Logical camera/gizmo/picking aspect remains independent of this target scaling; rounding can change each dimension by less than one pixel. This bounds retained payload, not total VRAM or temporary old/new allocation overlap during resize. No native memory allocation or resize-peak measurement is claimed.

Primary sources consulted 2026-11-04: [Khronos multisampling](https://docs.vulkan.org/tutorial/latest/10_Multisampling.html), [wgpu attachment resolve](https://docs.rs/wgpu/latest/wgpu/struct.RenderPassColorAttachment.html), [format flags](https://docs.rs/wgpu/latest/wgpu/struct.TextureFormatFeatureFlags.html), [adapter format capabilities](https://docs.rs/wgpu/latest/wgpu/struct.Adapter.html) and [Unity URP antialiasing](https://docs.unity.com/en-us/engine/6000.0/manual/render-pipelines/universal-render-pipeline/anti-aliasing). Installed wgpu30.0.1 source confirms device-feature restrictions. MSAA fits the reported geometric silhouette aliasing, with extra sample storage/bandwidth. Composite FXAA could avoid those attachments but would require an unmeasured image filter and detail tradeoff; TAA needs history/motion information and temporal-artifact handling. Neither alternative is implemented. MSAA does not solve shader/specular/texture aliasing.
