# M8 bounded mlua debugger and isolation trial

Date: 2026-11-04. This is a disposable `/tmp` experiment, **not a language selection, engine integration or completed creator workflow**. [The preceding comparison](M8-tooling-trial.md) owns LSP observations; [decision0011](../decisions/0011-behavior-scripting-experiment.md) owns the existing provisional scripting experiment. C# remains a credible untested candidate. No workspace manifest, lockfile, engine code or user editor configuration changed for this trial.

## Observed result

Pinned mlua0.12.2 with a narrow dependency-only safe locals extension executed the real Lua5.4 follower over a Content-Length framed DAP stdio transport: breakpoint line8, stack/scopes/variables, `speed=2`, `enabled=true`, `target=target-2`, `dt=.25`, next to line9 with `step=.5`, then continue to `x=.5`. Repeated variable requests reuse bounded handles; a prior pause's reference is rejected after stepping. A second actual DAP session disconnected while paused and joined its worker cleanly. A third filled64locals with control characters, observed a bounded same-request error for the escaped oversized variables reply, confirmed the VM remained paused at line8, then stepped to9 and continued successfully. This is a scripted protocol client, **not external IDE launch/attach, Kate integration or end-user breakpoint acceptance**.

Functional assertions passed:128 normal calls plus a coroutine stop; nil locals, shadowed names, invalid indexes, cyclic tables and a GC-rooted table retained beyond its hook; aggregate DTO bounds; stop while paused, cancellation of an actually running loop, channel disconnect and paused disconnect. The controller advanced28 heartbeat iterations while paused and19 while the VM ran, without owning a VM handle. These are small threaded controller checks, not measured editor-frame responsiveness.

Logical state isolation also passed: source main compiled once, fresh allowlist environment and fresh module/update closure on each evaluation; mutable globals, module upvalues, library entries, property tables and resolved input copies did not contaminate retry. Object1's staged success followed by object2's failure committed neither object nor time. Repair/retry matched a fresh VM's successful run: `[.5,.5]`, tick1. Module initialization, update, whole-tick instruction budgets and VM memory-limit failures were exercised. Authored source is restricted to text; only internally dumped bytecode is admitted by the alternate cache trial.

## Safe accessor boundary and review

The exact registry crate is [mlua0.12.2](https://static.crates.io/crates/mlua/mlua-0.12.2.crate), SHA-256 `7a7ae6b65bf54b7fdd4cf5b6f44f60862350ebf3fe3779b3a9cc005e7fa14f81`. Its original MIT license and local Lua5.4.9 distribution license are retained with the fixture. mlua-sys0.13.0 and all resolved Rust versions are pinned in the isolated Cargo.lock. The system VM is dynamically linked, not bundled by that crate archive. Main-repository dependency notices were consequently unchanged.

The proposed `Debug::local(index: u32) -> Result<Option<(String, Value)>>` exists only inside disposable dependency source and is gated to Lua5.4. It rejects0 and values above `c_int::MAX`, reserves2 stack slots, guards the original top, invokes `lua_getlocal`, distinguishes no local from a nil-valued local, immediately copies the returned name, and uses the existing fallible `RawLua::try_pop_value` GC-rooting path. It exposes no raw VM pointer to host code. The trial crate uses `#![forbid(unsafe_code)]`, safe `Lua::new_with`, no DEBUG library and no `send` feature.

An important reviewed restriction is enforced: the borrowed Debug's stored state must equal RawLua's currently selected active state **before any stack access**. Ordinary hooks use `callback_error_ext`'s StateGuard; ordinary coroutine tests alone would miss nested state changes. The actual regression retains an outer Debug borrow, enters `Lua::scope`, invokes a scoped Rust callback through another coroutine, and verifies the outer accessor returns an error; after StateGuard restores the outer state, it reads that local successfully. Source review identified this requirement before runtime acceptance. The pinned-source analysis was independently reviewed through the root's Astra assignment; this is a bounded engineering review, not a formal proof of all mlua/VM soundness.

No auxiliary-reference-stack exhaustion was injected. Stack balance is evidenced by the guard's own invariant and successful repeated calls/coroutine, without exposing a raw stack-inspection API. No Miri, sanitizer, hostile native-library or cross-platform verification ran. The experiment does not waive the engine's unsafe-code policy or adopt a permanent vendor fork.

## Isolation, budgets and deliberately limited protocol

One dedicated owned thread creates and destroys the VM; Lua handles remain on that thread. Commands/events use capacity8 channels. Pause waits poll cancellation every5ms; running code checks cancellation through hooks. Snapshots become plain owned DTOs inside the hook, bounded across the complete snapshot to8frames,64locals,2,048nodes and64KiB string content; names/values are additionally limited to256characters, table depth2 and16entries. Raw table iteration invokes no `__pairs`/`__index`; cycles and opaque values become markers. A hostile `__pairs` fixture was bypassed successfully. Serialization has additional bounded structural and escaping overhead. Outgoing replies are preflighted against their actual encoded65,536byte body limit; oversized variables replies produce a bounded error with the same request sequence and a fixed diagnostic, retaining paused state and cached handles. The actual control-character DAP fixture exercised this expansion path, not just ASCII content. The header adds its small framing overhead to that body limit.

The DAP trial reads at most1,024bytes per header line,4,096header bytes and65,536body bytes; malformed, duplicate, unknown, oversized and truncated framing fails closed. Variable trees are flattened once per pause with bounded epoch handles; Next/Continue invalidate frames and variable references before execution resumes. Epoch exhaustion after1,024pauses errors instead of wrapping. A duplicate configurationDone errors instead of leaving an unowned second VM. The implemented transport is deliberately one source/one breakpoint/one worker and line-next, with no general launch configuration, changing breakpoint set during execution, arbitrary expression evaluation, stepping depth, source-version conflict handling or IDE extension. Those remain integration work.

The environment has no mutable global fallback. Its only library capability is a fresh `math` table containing immutable C `min`; a fresh host table resolves fresh copies from one immutable tick-start target. IO/OS/debug/package/loaders/coroutines/metatable controls/pcall, `_G`, random and randomseed are absent. Trusted host callbacks remain a separate bounded-code obligation. Evaluation instructions are limited to20,000 and a whole atomic tick to100,000, checked every100VM instructions; VM memory is limited to2MiB in functional cases. The running debugger cancellation fixture permits a larger finite instruction count so it stays active long enough to measure controller progress. This is logical host-state transaction isolation, **not VM heap rollback or a hard wall-time sandbox**.

## Release cost and limits

The retained raw matrix compares cached compiled main plus fresh module closure against internally generated unstripped bytecode reloaded on each evaluation. Both reconstruct the allowlist and copied inputs each time; update functions are never cached. Both cache representations are prepared outside timing to keep setup comparable; VM memory therefore includes retained compiled mains even in bytecode mode, and Rust-owned bytecode/source/DTO storage is excluded. These figures do not establish a production bytecode-only memory requirement.

Workloads are1/32/256objects, either one shared source or one distinct source per object. Each case has7warmup ticks and20measured ticks; every output is checked against `.5`. Reported medians use the upper middle sample of20; p95 is the19th sorted sample. All20sorted observations are retained, without temporal ordering. Memory observations use the VM allocator's `used_memory`, with a separately timed explicit collection after sampling; ordinary VM GC remains active during ticks. The cost fixture permits64MiB VM memory. The host is this laptop's Intel Core i9-13900H on Linux, Rust1.99.1, system Lua5.4.9, powersave governor, with no CPU pinning. The root serialized the release build and provided a quiet sampling window without other project builds. No GUI/GPU run or cross-engine comparison is implied.

The first count-budget-hook matrix has12rows and took approximately.304s; its raw data is retained separately. It is a preliminary observation, not the final count-only versus line-debug-hook comparison. Distinct-source compiled-main p95 was noisy in that initial sample, so no universal cache advantage is inferred. The final24-row count-only versus count+line-hook matrix took approximately.583s. At256objects:

| Source/cache | Count-budget median/p95 | Plus line hooks median/p95 | VM bytes after explicit GC |
| --- | --- | --- | --- |
| Shared / compiled main |2.287/2.417ms |2.626/2.695ms |16,425 |
| Shared / bytecode reload |2.894/3.045ms |3.235/3.383ms |16,273 |
| Distinct / compiled main |2.354/2.456ms |2.754/2.862ms |309,277 |
| Distinct / bytecode reload |2.805/2.962ms |3.169/3.351ms |215,213 |

The last256object tick delivered49 count-hook callbacks or2,097 total callbacks with line hooks enabled. This measures enabled hooks without pausing/snapshotting each line; pause-inspection cost is a separate unmeasured workload. In this small final sample, compiled-main evaluation was faster, while retaining its last environment for each distinct main consumed additional VM memory. Explicit post-sampling GC ranged roughly10–120microseconds in these256object cases. The result supports keeping compiled-main/fresh-closure as the simple trial default, with a measurable memory/cache tradeoff; it does not justify a permanent engine/language choice, stable latency guarantee, or comparison with another engine.

## Reproduction, failures and remaining gates

The [fixture archive](m8-lua-debug-fixture.tar.gz) and [hash manifest](m8-lua-debug-fixture.sha256) preserve exact source, dependency archive/patch/licenses, isolated Cargo.lock, tool/CPU provenance, raw functional/DAP/cost results and build logs. Reproduction instructions explain dependency extraction/patching and system prerequisites. Initial compilation failed on the changed mlua0.12 import path (`mlua::debug`, not root exports) and a partially moved harness worker; both harness errors were fixed. The first locked release build passed in2.47s. The final matrix/text-only-source build passed in2.63s, followed by one final functional run, both ordinary DAP sessions and the24-row cost run. A later framing-only release build passed in4.86s; targeted framing assertions and all3DAP sessions then passed. Its first Python control-case attempt assumed an optional error-response body existed and raised KeyError; `.get("body", {})` fixed that client assumption, the failed log was retained, and the unchanged Rust adapter passed the follow-up. Backend runtime/accessor and release-cost evidence was reused because those functions/dependencies/configuration were unchanged by the framing-only edit; the24-row matrix was not repeated. The plain functional binary uses assertions rather than a Cargo test harness; these are actual executable assertions, not a claim of added engine regression tests. No engine workspace test gate or standalone Clippy/sanitizer lane ran for these evidence-only repository writes. Local Markdown links/whitespace, archive SHA/extraction/patch application and captured-result assertions passed. This trial does not overwrite scenes or interact with the desktop/clipboard.
