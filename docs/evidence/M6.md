# M6 content and iteration evidence

Date: 2026-11-04. Complete within the documented local Linux OBJ/WGSL scope; source implementation alone was not acceptance. See [decision0008](../decisions/0008-content-import-and-refresh.md) for the selected route and exact transaction/compatibility boundary.

## Implemented scope

One owned-content route: bounded triangle-only OBJ positions/flat normals/indices. Stable catalog IDs, project-relative source confinement, independent catalog revisions/baselines and safe source rename. Versioned SHA256 cache recipe and bounded native/serialized meshes; cache is rebuildable and ignored by Git. Scene-v2 mesh assignment participates in shared persisted undo/redo; strict scene-v1 loading preserves old history and rejects v2 fields. Saving explicitly upgrades to v2. Logistics files remain separate.

Renderer uses actual mesh geometry/bounds/triangle selection with retained GPU buffers, shared by editor/standalone. Preview freezes resolved Arc mesh snapshots until Reset. Explicit project shader refresh validates one fixed-contract WGSL candidate before swapping; failures retain last valid pipeline. Project switching resets the pipeline to built-in and preserves the GPU handle. Catalog changes persist independently; scene Undo/Discard never deletes or renames source files. Unknown/missing content retains refs and reports placeholders. Scene/history asset refs block cross-root Save As.

## Proportionate verification

Focused workers verified scene-v1 migration/v2 history and CLI, importer/cache/confinement/recovery/rename and revisions, renderer triangle selection and shader candidate failure recovery, and strict MCP revision/argument forwarding. The importer capacity test exercises the real32MiB aggregate boundary and costs about21s debug; this is a meaningful expensive test, not a throughput benchmark. FIFO tests invoke bounded CLI children so a regression cannot hang the suite. The final gate/actual native/client/measurement evidence will be recorded after execution.

Astra review identified and fixed Open GPU-handle/pipeline retention, undo-history dependencies during Save As, sourcealias rename hazards, FIFO blocking before file checks, missing-reference diagnostics, stale preview geometry status and absent-vs-null command arguments. No hostile same-user filesystem race or GPU shader sandbox guarantee is implied.

## Release-validation defect and correction

The first release native capture failed Vulkan validation with VUID10684 despite rendering a window. Earlier M5 release logs contained the same messages; the old uppercase-only ERROR check missed mixed-case Validation Error. Debug logs were misleading because upstream HAL explicitly suppresses this VUID. These captures are failed evidence, not passes. Root corrected M5 evidence and introduced the scanner/regression rather than suppressing the symptom.

A controlled dependency probe and independent spirv-val established the real fix: SPIR-V1.6 outputs for scene/composite/project/egui failed; actual1.3 outputs passed. A narrow fully sourced/licensed HAL patch caps emitted version and removes the10684 filter. See [decision0009](../decisions/0009-spirv-validation-compatibility.md). The corrected integrated release run rendered92frames at tick10, imported-scene fingerprint21b8871e9039669d,2draws and exactly2mesh uploads/1224payloadbytes across the entire run (720cube +504pyramid), not per-frame uploads. It passed `scripts/check_vulkan_log.py` with raw layer output. Native resources and actual geometry remained shared. No shader-performance win or broad compatibility claim is inferred.
