# M3 authoring verification

Date: 2026-11-04. M3 completed within the documented local Linux scenario-authoring scope.

## Scope and architecture

The first native editor uses egui/eframe with wgpu restricted to Vulkan at build and runtime. The M2 ash viewer remains a separate executable. Both use the same core simulation. Shared `ProjectSession` owns dirty/saved baseline tracking and persistence; CLI/editor share `ProjectLock` and Scenario validation/history. See [decision 0004](../decisions/0004-editor-session-and-ui.md) and the [editor quickstart](../../crates/ruster-editor/README.md).

One logistics scenario is authored. Source/transport/destination are selectable views, not a new general entity/component system. Runtime state is separate from authored configuration; Reset explicitly adopts edits. Native MCP remains M4.

## Focused verification

- Core/CLI: 19 tests passed in 1.28 seconds, including three new session contract cases and an extension of the existing CLI concurrency case. Tests cover full-baseline conflicts, failed-save preservation, duplicate identity, dirty history, shared lock aliases and nonblocking busy behavior.
- Editor: four focused tests protect pre-desktop argument failures, invalid-draft recovery/runtime isolation, destructive-action recovery, and pending Save As failure/success continuation. Initial framework dependency codegen/test build took 65 seconds. The final Vulkan-only/inspection feature build and tests took 40.32 seconds; these are build costs, not test execution times or controlled build comparisons.
- Independent Astra static review found no blocking data-loss/resource-lifetime issue in shared sessions, CLI guard lifetimes, viewer caching/scheduling or editor recovery. This does not replace runtime UI verification.
- [Viewer performance and Vulkan evidence](m3-performance.md) records the matched release CPU samples and zero-error synchronization-validation smoke. Allocation counts, power and input-latency distributions were not measured.

## Desktop isolation

During work the user requested test windows on workspace 2 while using workspace 1. A narrow local Hyprland rule routes initial Ruster viewer/editor titles silently with no initial focus. Viewer routing and unchanged active workspace were observed. Tests must not change workspace, use global pointer/key input or replace the user's clipboard. The optional default-off eframe inspection feature enables per-app UI input/tree/framebuffer checks on loopback; it is test instrumentation, not the product MCP interface.

## Integrated gate

`CARGO_BUILD_JOBS=4 python3 scripts/check.py --full` passed against the integrated working tree: 13 tooling tests, 26 Rust tests, formatting, strict Clippy and documentation links/whitespace. Wall time 45.90 seconds: 10.54 seconds Clippy/check compilation and 34.15 seconds test-profile compilation after narrowing graphics features. The tooling tests took 0.604 seconds; Rust test bodies completed below the printed 0.01-second resolution per group. This first feature/profile build exceeds the 30-second warm feedback target, but is not a warm-suite measurement. No tests were removed or repeated merely to obtain a faster number. Inspection-feature supplemental tests/Clippy also passed; the optional feature is outside the default runner.

A later visual check found missing decorative glyphs, which were replaced with plain labels. Root also found that backend log messages had no installed logger; a minimal warning/error stderr logger now exposes wgpu/Vulkan diagnostics. After those changes and the direct existing `log` dependency, the final full gate passed again in **3.66 seconds** (same 26 Rust/13 tooling tests). This repeat validated changed inputs, rather than repeating an unchanged green run for timing. Final editor Windows compilation passed in 2.74 seconds.

The runtime editor launch reported NVIDIA GeForce RTX 4060 Laptop GPU · Vulkan and mapped to workspace 2 without changing the active workspace 1.

`CARGO_BUILD_JOBS=4 cargo check --locked --workspace --target x86_64-pc-windows-gnu` passed for all four crates in 24.30 seconds. This checks compilation only: no linked Windows package or Windows runtime/UI is verified.

## Native interaction and graphics verification

An independent Terra agent followed the quickstart against the actual native editor using app-scoped input, widget-tree observations and framebuffer capture. It exercised valid/invalid/recovered edits, runtime Reset/Step/Run/Pause, authored undo/redo while retaining runtime observations, Save As rejection for an existing path, successful save/reopen, New, unsaved close/invalid Save/Cancel/Discard, and keyboard shortcuts. Tab focus was observed moving Open → Save → Save As through AccessKit focus IDs. The 960×640 layout was rendered and inspected, then restored to 1400×900. [Editor capture](m3-editor.png) shows the label correction; it is not a standalone usability study.

The hidden Wayland surface initially stopped painting and inspection timed out. A temporary editor-class `render_unfocused=true` rule allowed app-scoped interaction/capture without switching workspace 1. A three-second idle sample before that rule measured one 100-Hz CPU accounting tick (0.33% of one core), with no inspection polling. That is a debug, occluded-window observation, not an editor release-performance benchmark. The independently measured interaction timings and their limitations are recorded by the walkthrough evidence.

The diagnostics-enabled editor was launched with `VK_INSTANCE_LAYERS=VK_LAYER_KHRONOS_validation` and `VK_VALIDATION_VALIDATE_SYNC=1`, the extracted layer paths, and loader diagnostics. [Recorded excerpt](m3-editor-validation.txt) confirms instance/device layer insertion, NVIDIA Vulkan selection and layer unload after shutdown. No validation error or synchronization hazard was reported during the edit/resize/close journey. Two loader notices say the environment variable adds the validation layer; these expected notices were visible through the new stderr logger and are not silently counted as zero warnings. This does not audit untested devices or every rendering path.

## Recovery correction and final acceptance

The walkthrough found a stale field-validation diagnostic when correcting an invalid draft back to the authored value (Apply and Revert then disabled). Inspector validation is now tracked separately from operation errors. Returning to authored values clears that obsolete diagnostic and requests a repaint; unrelated failed-save/conflict messages remain visible. The existing recovery regression was extended, not duplicated. Targeted test, strict Clippy and the native reproduction passed. The final full integrated gate then passed in **3.53 seconds**, retaining 26 Rust and 13 tooling tests. The final editor Windows compile check passed in 0.42 seconds, and the default (inspection-disabled) executable was rebuilt.

[Independent walkthrough evidence](m3-editor-walkthrough.md) records the precise steps and gaps. In one instrumented automation sequence, valid-edit confirmation took 0.537 seconds; invalid feedback appeared at 1.069 seconds from the same start; recovery was confirmed at 1.469 seconds (0.400 seconds after feedback). These are debug app-scoped automation timings, not human usability or release latency claims. New was exercised; native Duplicate was not, although core/model duplicate contracts were tested.

All test editor windows were closed. Reloading the compositor configuration removed the temporary background-rendering rule; config validation was clean and active workspace remained 1. The persistent workspace-2 launch rule remains. Documentation-only final changes were checked separately without rerunning unchanged Rust/GPU evidence.

M4 native MCP is next. Wider hardware/Windows runtime, external human walkthroughs, screen-reader audit, file browser/docking, arbitrary entities and real 3D rendering are outside this delivered milestone. The separate editor and ash rendering paths are an explicit temporary architecture tradeoff, not a completed general-purpose engine renderer.
