## Supported route and authority

`Host::native_scene_observation(&self) -> SceneObservation` in
`crates/ruster-editor/src/scene_editor/connection/native.rs` is a local read-only
Host seam, not a new MCP endpoint. The normal **AI connection…** window renders
complete `Scene guard session_token:` and `Scene guard revision:` labels, alongside
Scene, Editor session (connection incarnation), Project generation and Observation
owner. **Connect AI** opens the existing approval preview with separately prefixed
`Frozen Scene guard session_token:` / `Frozen Scene guard revision:` labels.
Opening or canceling the preview does not start a listener or adapter.

The token is the existing scene optimistic-concurrency identifier, generated by the
same `SceneEditor::scene_guard_token` function used by command dispatch and replies.
Bridge dispatch uses the locator's editor incarnation as its nonce. It is **not**
the private socket authorization capability: observation does not call bind,
approve, dispatch or expose that capability. No new logging/secret dump exists.
The existing Bridge authorization gate remains unchanged.

Observation captures scene ID, exact decimal revision, editor incarnation, project
generation, socket-bound owner (if any), and connection state together. Before any
adapter exists it explicitly says **No adapter owner observed; prelaunch observation
does not bind a future owner**. It never substitutes a preliminary adapter or claims
executable provenance. Confirmation compares the complete frozen observation with
current state as well as the pre-existing locator/owner/transition checks; scene
session/revision changes discard consumed consent. The production registration
worker remains fail-closed and unmodified.
