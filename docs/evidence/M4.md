# M4 native agent workflow evidence

Date: 2026-11-04. Scope: local Linux editor-owned logistics authoring proof. Working architecture is [decision 0005](../decisions/0005-live-mcp.md); semantics are the [command contract](../M4-COMMAND-CONTRACT.md). Defaults were agent-selected under the accepted roadmap.

## Demonstration

Built native editor with optional inspection instrumentation and native ruster-mcp. Started a disposable example copy with RUSTER_MCP_ENABLE=1; attached official Python MCP SDK 2.3.0 over stdio using the editor's explicit private socket. Negotiated protocol 2025-06-18 and discovered inspect/edit/undo/redo/replay. `scripts/mcp_demo.py` is the repeatable SDK demonstration; connection commands are in the editor and adapter READMEs.

The SDK inspected revision0/capacity2, replayed ten ticks (20 delivered, stock10), edited capacity to4 with exact token/revision, and replayed ten ticks (30 delivered, stock0). Returned before/after diff and revision1 identified the edit. Stale revision, zero capacity and >10,000-tick replay were rejected. Live preview remained paused at tick0 with its original runtime configuration; it became stale as intended. No automatic save occurred.

App-scoped egui inspection then clicked the actual editor Undo button: capacity returned to2/revision2. The SDK's earlier revision was rejected. Native inspector text was changed to5: MCP mutation failed with drafts_pending. Native Apply committed5/revision3, making the prior agent revision stale again. Preview tick/state remained unchanged. Native Save persisted the disposable copy and cleared dirty state. Framebuffer inspection confirmed the inspector5, revision3 unsaved marker before Save, and stale preview showing original capacity2. These are instrumented human-control-path actions, not an external human usability study.

Changing socket permissions from0600 to0666 made the adapter reject attachment with bridge_unavailable; permissions were restored. A 10,000-tick replay round trip took65.3ms in one debug/background-rendering sample, including scheduling/polling; no comparative performance claim. Strict wire/domain tests cover unsupported/invalid inputs and lifecycle. Session-generation tests cover reopening identical scenario identity/revision and Save As identity preservation. A bridge regression specifically covers expiration before editor dispatch, including the timeout-lock race found by Astra review.

## Environment and verification

CachyOS, Hyprland, NVIDIA RTX4060 Laptop GPU, Vulkan editor backend. Workspace2 routing was observed before app-scoped input; workspace1 remained active. Hidden Wayland rendering initially caused expired bridge requests. A temporary editor-class render_unfocused rule permitted background verification; this is an altered rendering condition. No global input or clipboard changes. Inspection is test-only and independent of product MCP. Temporary rule/app cleanup is recorded in status.

Initial integration failures: missing cargo on shell PATH (used ~/.cargo/bin and existing runner fallback); stale lock after manifest changes (explicit offline cargo check bootstrap); Python SDK2.3 uses snake_case response attributes (demo corrected); hidden UI expiry (documented above). A restart briefly overlapped the inspection port; the extra test instances were stopped and final run used a fresh port. No failed attempt was counted as acceptance evidence.

Final change gate and final native rerun results are recorded in [status](../STATUS.md). The full gate includes protocol/core/editor tests, strict Clippy, formatting, docs and tooling tests. Root reviewed actual integrated diffs and reused focused worker findings; Astra reviewed session/transport ownership and bounds. No new Vulkan/unsafe rendering code was added, so previous M3 validation evidence was retained; this is not a new GPU validation audit. Windows, other clients/protocol revisions, headless hosting, adversarial same-user isolation and concurrent cancellation are not verified/support claims.
