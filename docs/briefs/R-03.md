# R-03 · A Lua reference, and discovery for AI apps

Lane Repair · Size M · Depends on: nothing

**Outcome.** A creator can look up every script function, and an AI app can
find out which components and script functions exist without guessing.

**Why.** Both workflows are first class. Today neither is documented for
anything built since 2026-11-17.

**Facts.** Checked 2026-11-27.

- `docs/BEHAVIOR-AUTHORING.md` was last changed on 2026-11-17 and describes
  the old numbered host API. Nothing documents coroutines, `host.on`,
  `host.raycast`, the collision callbacks or the component handles.
- The Lua API is registered in `rot-behavior/src/lua_component.rs`:
  `build_host_table` (about line 409), the module callbacks (about line
  3817) and the handle types.
- `rot-mcp/src/component_tools.rs` advertises component `type` as
  `mesh_renderer, collider, camera, light, animator, script`. The editor
  accepts `rigid_body`, `joint`, `character_controller` and `skin` too,
  because it parses a `ComponentInstance`, but no client can learn that.
- `component_mcp.rs:308` still tells clients about "four active Point and
  Spot slots" and "Object Lua API 1/2". Both are obsolete.
- The tool list is 14,457 bytes against a 15 KB budget. Reference text
  cannot go into `tools/list`.

**Do.**

1. Write `docs/LUA-API.md`: script shape and callbacks, every `host.*`
   function, every handle and its methods, each with its signature, one line
   of meaning and its limits. Add one complete example script at the top.
   Read the code for every entry; do not copy the old guide.
2. Add a test in `rot-behavior` that builds the host table and each handle,
   collects their keys, and asserts each name appears in `docs/LUA-API.md`
   (`include_str!`). A function added later without documentation then fails
   the gate.
3. Add a component catalog in `rot-scene`: for each `Component` variant its
   wire `type`, its fields, each field's kind, default and range. Add a test
   that serializes one instance of every variant with non-default values and
   asserts that every key is in the catalog. Build the instances with a
   `match` that has no `_ =>` arm.
4. Serve both through the existing `rot_tools` tool: `{"action":"describe",
   "name":"topic:lua_api"}` and `"topic:components"`. List the topics in
   `rot_tools` `list`. Mention them in the server `instructions` string in
   `rot-mcp/src/main.rs` in one sentence.
5. Make the advertised `type` enum and collider shape enum in
   `component_tools.rs` match the catalog. Remove the obsolete guidance at
   `component_mcp.rs:308`.
6. Delete `docs/BEHAVIOR-AUTHORING.md` and fix links to it.

**Done when.**

- Both drift tests pass and fail when a function or field is removed from
  the document or catalog.
- `tools/list` stays under 15 KB; put the measured size in the commit.
- A real AI client, in a throwaway project with a project-level MCP config,
  is asked to "add a Rigid Body to the cube and write a script that casts a
  ray down each frame and logs the hit". It succeeds using only what
  discovery returned. Paste its tool calls in the commit message.

**Not now.** The creator guide for the editor (`R-05`). New MCP tools.
