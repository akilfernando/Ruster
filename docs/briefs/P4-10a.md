# P4-10a · Scene loading, pause, time scale and quit

Lane Play · Size M · Depends on: P4-12a

**Outcome.** A script loads another scene, restarts the level, pauses and
slows the game, keeps values between scenes, and quits.

**Why.** `SceneManager.LoadScene`, `Time.timeScale` and `Application.Quit`
are in every Unity game. Unreal has Open Level and Set Game Paused.

**Facts.** Checked 2026-11-27.

- A script cannot load a scene. The only scene change is one authored
  "startup transition": a title scene that moves to one target scene on an
  action (`rot-app/src/creation.rs`, `StartupTransition`;
  `.rot-project.json` field `startup_transition`). It prepares the target
  on a worker thread so the switch does not stall.
- Build packages the startup scene and that one target.
- There is no time scale, no pause from a script and no quit function.
- All state is lost on a scene change.

**Do.**

1. Project Settings, Build gets a "Scenes in Build" list, as Unity has:
   scenes in order, the first is the startup scene. Build packages each
   listed scene and its assets.
2. `host.load_scene(name)` accepts a scene's name or file name from that
   list. The current tick finishes, the new scene is prepared off the main
   thread with the existing transition path, then replaces the current one.
   `host.reload_scene()` loads the current scene again. A name that is not
   in the list is a script error that lists the valid names.
3. In editor Play, `load_scene` switches the running game. Stop always
   returns to the scene that was open for editing, unchanged.
4. `host.globals` is a table that survives scene loads for the length of a
   Play session. It holds numbers, strings, booleans and nested tables.
5. `host.set_time_scale(x)`, `host.time_scale()`: scripts, physics and
   animation receive `dt * x`. 0 pauses them. `host.unscaled_dt()` is
   always the real tick length. Coroutine `wait` uses scaled time;
   add `host.wait_unscaled(seconds)`.
6. `host.quit()` closes the player. In the editor it stops Play.
7. The startup transition keeps working.
8. Add all of it to `docs/LUA-API.md`.

**Sample.** Three levels. The flag loads the next one. Escape pauses with
time scale 0. The score lives in `host.globals`.

**Done when.**

- Runtime tests: load by name; reload restores the initial state; a wrong
  name errors with the list; `host.globals` survives a load; time scale 0
  stops physics and `on_update` time but not `wait_unscaled`.
- A player test plays level 1 to the flag and arrives in level 2.
- Loading a 5,000-object scene keeps the worst frame under 16 ms on the
  main thread. Measure in release with the existing start-transition test
  as the pattern.
- Build from the sample contains all three scenes and runs from a moved
  folder.

**Not now.** Additive loading, streaming levels, objects that survive a
load, loading screens with a progress value.
