# P4-13 · Locomotion blending and animation events

Lane Play · Size M · Depends on: P4-S1

**Outcome.** A character blends smoothly from idle through walk to run as its
speed changes, and a clip can call a script at a chosen moment, such as a
footstep.

**Why.** A 1D blend tree and animation events are the two Animator features
every Unity character controller uses. Unreal's blend space and anim notify
are the same things.

**Facts.** Checked 2026-11-27.

- `AnimatorState` (`rot-scene/src/animation.rs`, about line 552) has `name`,
  `clip`, `looping` and `speed`. A state plays exactly one clip.
- The state machine has Bool, Float, Int and Trigger parameters, conditional
  and exit-time transitions, Any State and cross-fade. It is evaluated in
  `rot-behavior/src/animator.rs` and blended by `apply_blended_poses`.
- Blending two poses already exists for cross-fades (position and scale
  linear, rotation shortest-path slerp).
- The Inspector edits the state machine as lists
  (`rot-editor/src/scene_editor/component_inspector.rs` and
  `component_animation.rs`).
- Scripts get no callback from a clip.

**Do.**

1. A state's motion is a clip, as now, or a blend tree: an optional
   `blend` field holding a Float `parameter` name and a list of `clip` and
   `threshold` pairs, at least two, in rising threshold order.
2. Evaluate a blend tree by finding the two neighbouring thresholds around
   the parameter value and blending their poses by the fraction between
   them. Below the first or above the last threshold, play that clip alone.
3. Keep the clips in step: advance one shared normalized time for the tree,
   at a speed that is the same blend of the clips' lengths, so feet do not
   slide when clips have different durations.
4. Events: a state has an optional `events` list of `time` (0 to 1 of the
   clip) and `name`. When playback crosses a time, call
   `on_animation_event(transform, props, name, host)` on the scripts of the
   Animator's object. A looping clip fires each loop. During a cross-fade
   only the target state fires. In a blend tree, events come from the clip
   with the larger weight.
5. Inspector: a Motion dropdown per state, Clip or Blend Tree. A blend tree
   shows its parameter and a list of clip and threshold rows. An Events
   list per state with a time field and a name. The clip preview scrubber
   shows event marks.
6. Lua Animator handle: `state_weight(name)` for debugging. Document the
   new callback.
7. Add to the component catalog, the MCP schema and `docs/LUA-API.md`.

**Sample.** The player's idle and run states become one Locomotion state
blending idle, walk and run on `speed`. A footstep event plays a sound.

**Done when.**

- Tests in `rot-behavior`: parameter halfway between two thresholds gives
  the halfway pose; below the first threshold equals the first clip; two
  clips of different length stay phase-aligned for 300 ticks; an event at
  0.5 fires once per loop; no event fires from the fading-out state.
- A skinned-mesh test checks joint matrices of a blended pose.
- A player test runs the sample's locomotion state.
- The 10,000-script benchmark and the 5,000-object render benchmark are
  within 5% of their previous numbers.

**Not now.** 2D blend trees, layers and masks, additive clips, root motion,
inverse kinematics, retargeting, a node-graph editor.
