# R-04 · Script budget with the limits the player ships

Lane Repair · Size S · Depends on: R-02

**Outcome.** The 10,000-script budget is measured the way games run, and has
headroom again.

**Facts.** Measured 2026-11-27, release build, desktop in use.

- Budget: 10,000 script updates per frame in 2 ms
  ([budgets](../PARITY-PLAN.md#5-performance-budgets)).
- `bench_10k_script_updates_per_frame`
  (`rot-behavior/src/lua_component_tests.rs`, `measure_10k_workload`) runs
  with `tick_instructions: 100_000_000` and `memory_bytes: 128 MiB`. The
  player and the editor run `Limits::default()` (`rot-player/src/player.rs`
  about line 605, `rot-editor/src/behavior_worker.rs` about line 496).
- Logic only: p50 1.611 ms, p95 1.699 ms. Transform writing: p50 2.022 ms,
  p95 3.107 ms, which failed the benchmark's own 2.0 ms assertion.
- The transform-writing p50 reported by earlier packages rose from 1.913 ms
  (`P4-01`) to 1.934 ms (`P4-04`) to 1.973 ms (`P4-06`). Each package added
  per-tick work that runs even when a scene has no physics or animation.
- Physics is fine: 1,000 bodies, full step p50 0.769 ms against 4 ms.

**Do.**

1. Make the benchmark use `Limits::default()` and nothing else.
2. Close other heavy programs. Run it five times and record p50 and p95.
3. Time the stages of `step_component_with_input`
   (`rot-behavior/src/component_runtime.rs`) for the transform-writing case:
   script batch, physics, animation, world matrix resolve, draw frame build.
   Use `std::time::Instant` spans behind `#[cfg(test)]` or `perf record`.
4. Remove the work that is not needed for this scene. Look first at systems
   that run when their component count is zero, and at buffers cloned every
   tick for rollback when nothing wrote to them.
5. Rerun step 2. Put before and after numbers in the commit message.

**Done when.**

- The benchmark asserts with `Limits::default()`.
- Transform writing is at or under 1.80 ms p50 in three of three runs on an
  idle machine, and logic only is at or under 1.65 ms.
- `bench_1k_active_rigid_bodies` is within 5% of its previous numbers.
- The Measured column of the budgets table has the new numbers.

**If you cannot reach 1.80 ms.** Stop after one session. Put the stage
timings in the commit message, leave the best version that passes at 2.0 ms,
and add one Inbox line in [BACKLOG](../BACKLOG.md). Do not change the budget.
