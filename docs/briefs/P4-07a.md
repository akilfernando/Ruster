# P4-07a · Audio sources

Lane Play · Size M · Depends on: R-02, P4-S1

**Outcome.** A creator adds an Audio Source to an object, picks a clip, and it
plays, loops, stops and changes volume and pitch from a script. A 3D source
gets quieter and pans as it or the listener moves. It works on Windows too.

**Why.** Audio Source and Audio Listener are the Unity model. Unreal's Audio
Component is the same idea.

**Facts.** Checked 2026-11-27.

- Sound today is a "sound cue" property on a script.
  `host.play_sound("name")` queues a one-shot (`rot-behavior/src/audio.rs`).
  Gain and pan are computed once, when the cue is requested.
- Output is `rot-app/src/audio.rs` with `rot-app/src/audio/linux.rs`: kira
  0.12 on a cpal backend. On any other system `play` only sets
  `unavailable`. In `rot-app/Cargo.toml` both crates are under
  `[target.'cfg(target_os = "linux")'.dependencies]`.
- There is no looping, stop, pitch or runtime volume, and no component.
- Clips are WAV, decoded fully into memory by `rot-assets/src/audio.rs`.
- Cues are published only when a tick commits (`AudioBatch`). Keep that
  rule: a discarded tick makes no sound.

**Do.** Follow [recipe 4.1](../ARCHITECTURE.md#41-add-a-component).

1. Make output cross-platform. Move the kira and cpal setup out of
   `audio/linux.rs` into a module that compiles everywhere and uses cpal's
   default host. Keep Linux-only choices behind
   `rot-support/src/platform/`. Make both crates ordinary dependencies.
2. Component `AudioSource`: `clip` (sound asset), `volume` 0 to 1 (default
   1), `pitch` 0.1 to 3 (default 1), `looping`, `play_on_start` (default
   true), `spatial_blend` 0 to 1 (0 is 2D), `min_distance` (1),
   `max_distance` (50), `rolloff` (`logarithmic` default, or `linear`).
3. Component `AudioListener`, no fields. With none in the scene, the active
   game camera is the listener.
4. Runtime: the tick emits audio commands on commit (play, stop, pause,
   set volume, set pitch, set looping). Each rendered frame sends source and
   listener poses to the output so panning and distance stay live. Use
   kira's listener and spatial track.
5. Lua handle from `host.self:component("AudioSource")`: `play()`, `stop()`,
   `pause()`, `is_playing`, `volume`, `pitch`, `looping`, `set_volume(v)`,
   `set_pitch(p)`, `set_looping(b)`, `play_one_shot(volume)`. Also
   `host.play_sound_at(sound_property, position, volume)`.
6. When 64 voices are playing, stop the quietest one-shot to make room.
   Never stop a looping source for that.
7. Inspector section with a Preview button (reuse
   `component_sound_audition.rs`), Play Values, a speaker icon in the Scene
   view, and wire spheres for min and max distance on the selected source.
8. Sound cue properties keep working through the same output.
9. Add to the component catalog, the MCP schema and `docs/LUA-API.md`.

**Sample.** A looping ambience on the level, a 3D hum on the goal flag,
footsteps and jump as one-shots.

**Done when.**

- Tests against a recording backend that captures commands instead of
  opening a device: a loop starts and stops from Lua; moving a source from
  left to right of the listener changes pan sign and lowers gain with
  distance; a failed tick produces no command; the voice limit steals a
  one-shot.
- The Windows CI job passes with audio compiled in, not stubbed.
- A person hears it: preview in the Inspector and one Play run. Say who
  listened in the commit.
- Player test covers an Audio Source. Save, reopen and Build keep it.

**Not now.** OGG, MP3, streaming and mixer buses (`P4-07b`). Effects, reverb
zones, Doppler.
