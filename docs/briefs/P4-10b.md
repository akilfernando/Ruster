# P4-10b · Particles

Lane Play · Size M · Depends on: P4-12a

**Outcome.** A creator adds a Particle System to an object and gets sparks,
dust, smoke or a pickup burst, and a script can trigger a burst.

**Why.** Unity's Particle System and Unreal's Niagara are in almost every
scene. This package is the common subset of Unity's Main, Emission, Shape,
Color over Lifetime, Size over Lifetime and Renderer modules.

**Facts.** Checked 2026-11-27.

- There is no particle code.
- The renderer has a sorted transparent pass for `Blend` materials
  (`rot-render/src/lib.rs`), instancing with dirty-range uploads
  (`instancing.rs`) and fog in `surface.wgsl`.
- A draw frame is built in `rot-scene/src/draw_frame.rs` and consumed by
  `rot-render/src/component_preview.rs`.
- `math.random` becomes deterministic in `P4-12a`. Use the same generator.

**Do.** Follow [recipe 4.1](../ARCHITECTURE.md#41-add-a-component).

1. Component `ParticleSystem` with these fields and Unity's defaults:
   `duration` 5, `looping` true, `play_on_start` true, `max_particles` 1000,
   `start_lifetime` (min, max), `start_speed` (min, max), `start_size` (min,
   max), `start_color`, `gravity_modifier` 0, `simulation_space` local or
   world, `emission_rate` per second, `bursts` (time, count), `shape` (cone
   with angle and radius, sphere with radius, or box with size),
   `color_over_lifetime` (two to four color keys), `size_over_lifetime`
   (start and end multiplier), `texture` (optional asset), `blend` (alpha or
   additive).
2. Simulate on the CPU in a new `rot-behavior/src/particles.rs`, in flat
   arrays, with no allocation per tick once warm.
3. Draw camera-facing quads with one instanced draw per system in a new
   `rot-render/src/particles.wgsl`: depth test on, depth write off, in the
   transparent pass, sorted by system distance, fogged like other surfaces.
4. Lua handle: `play()`, `stop()`, `emit(count)`, `is_playing`.
5. Inspector section grouped like Unity's modules, collapsed by default.
   Play Values. The selected system also simulates in the Scene view in
   edit mode, with a small Play and Restart overlay, as Unity does.
6. Add to the component catalog, the MCP schema and `docs/LUA-API.md`.
7. Add a GPU probe that renders one additive and one alpha system and reads
   back pixels. It joins the list run by `python3 scripts/check.py --gpu`.

**Sample.** A burst when a coin is collected, dust puffs on landing, and a
looping sparkle on the flag.

**Done when.**

- Runtime tests: emission rate over two seconds, a burst count, lifetime
  expiry, `max_particles` holds, the same seed gives the same positions.
- Release benchmark: 100,000 live particles simulate in under 2 ms and draw
  in under 1 ms of GPU time at 1080p. Put both numbers in the commit and in
  the [budgets table](../PARITY-PLAN.md#5-performance-budgets).
- The GPU probe passes in debug and release.
- Screenshots of each sample effect in Play, viewed.
- Save, reopen and Build keep every field. The player test covers a system.

**Not now.** Collision, sub-emitters, trails, mesh particles, texture sheet
animation, GPU simulation, a node graph.
