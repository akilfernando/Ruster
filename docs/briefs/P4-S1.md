# P4-S1 · Platformer sample: first playable

Lane Play · Size M · Depends on: R-02

**Outcome.** `examples/rot-platformer` is a project a creator can open, play
and build: a skinned, animated character runs and jumps across platforms and
collects coins, using only features that already exist.

**Why.** The [Phase 4 exit](../PARITY-PLAN.md#3-phases) is this game, shipped.
The plan says samples grow as features land. Six Phase 4 packages are done
and none has been used in a real project yet. This package finds what breaks
when they are used together. Every later Play package adds to this sample.

**Facts.** Checked 2026-11-27.

- No model in the repository has a skin. The Kenney `character.glb` in
  `examples/rot-yard/Assets/Kenney` has four node animations and no skin,
  so GPU skinning has only ever drawn a synthetic test mesh.
- No test in the gate loads a project from `examples/`.
- `examples/rot-yard` is the pattern for a project: `.rot-project.json`,
  `Assets/`, scene files, a `README.md` with controls and licenses.
- Module scripts cannot feed the game HUD and cannot destroy an authored
  object. Work around both here; `P4-09a` and `P4-12a` fix them.
- Colliders are boxes and spheres only until `P4-11`.

**Do.**

1. Create the project. Reuse the Kenney platform models and coin from
   `examples/rot-yard/Assets/Kenney`.
2. Add a CC0, skinned, humanoid character with idle, run and jump clips, as
   one `.glb`. Kenney "Mini Characters" and Quaternius "Universal Base
   Characters" are both CC0. Commit only CC0 assets. Record the source URL
   and license in the README.
3. Build `level-1.scene.json` in the editor, through MCP where you can:
   - Platforms with Box Colliders, a kill plane below, a goal flag.
   - The player: Character Controller, the skinned model, an Animator state
     machine with a `speed` float and a `grounded` bool driving idle, run and
     jump, and `player.lua` that reads `move_x`, `move_z` and `jump` actions,
     applies gravity, calls the controller's `move`, turns to face the move
     direction and sets the animator parameters.
   - A camera with `follow_camera.lua` that keeps it behind and above the
     player and pulls it in with `host.shapecast` when a wall is in the way.
   - Ten coins as sensor colliders. `coin.lua` disables its object in
     `on_trigger_enter`, emits a `coin` event and plays a sound cue.
   - `game.lua` counts coins with `host.on("coin", ...)`, logs the score, and
     puts the player back at the start when they fall.
4. Add a test in `crates/rot-player` that loads the scene from
   `examples/rot-platformer`, steps 600 ticks with a recorded input sequence
   and asserts that the player stands on the second platform and that at
   least one coin is disabled.
5. Build the project to a folder and run it from another location.
6. Fix each defect you find if it is small. Otherwise write a failing test
   marked `#[ignore]` with the reason, and one Inbox line in
   [BACKLOG](../BACKLOG.md).

**Done when.**

- The new test passes in the gate.
- Screenshots viewed: the level in the Scene view, the character mid-run in
  Play, and the Animator section of the Inspector.
- A release build of the level holds the frame budget; record the frame
  time from the Stats overlay.
- The built folder runs after being moved.
- The README lists controls, what the sample shows, each asset's source and
  license, and what is still missing.
- The commit message lists every defect found, fixed or logged.

**Not now.** Enemies, menus, music, gamepad, several levels. Each arrives
with its package.
