# P4-09b · Cameras: priority, switching and blending

Lane Play · Size S · Depends on: P4-S1

**Outcome.** A scene has several cameras. A script switches between them, and
the view blends from one to the next.

**Why.** Unity renders the enabled camera with the highest depth and
Cinemachine blends between virtual cameras. Unreal has Set View Target with
Blend.

**Facts.** Checked 2026-11-27.

- The game camera is one id fixed at authoring time:
  `ComponentScene::gameplay_camera` (`rot-scene/src/component_scene.rs`).
- The Lua Camera handle has `fov`, `enabled`, `set_fov` and `set_enabled`.
  Enabling a second camera does not make it the view.
- `CameraView` is `Orbit` (legacy) or `Transform` with a perspective or
  orthographic lens.

**Do.**

1. Add an optional `priority` (whole number, default 0) to the Camera
   component.
2. The game view uses the enabled camera with the highest priority. On a
   tie, `gameplay_camera` wins, then the first in Hierarchy order. A scene
   with no enabled camera shows the existing empty state.
3. Lua on the Camera handle: `priority`, `set_priority(n)`.
   `host.active_camera()` returns the handle in use.
   `host.set_active_camera(cam, { blend = seconds })` raises that camera
   above the others and blends position, rotation and field of view over
   the time given, with ease in and out. Blend 0 cuts.
4. A blend runs on rendered frames using the two cameras' current poses, so
   a moving target camera stays correct.
5. Inspector: a Priority row. "Active Camera" shows which camera the game
   will use and why.
6. Add to the component catalog, the MCP schema and `docs/LUA-API.md`.

**Sample.** A second camera overlooks the goal. Reaching the flag blends to
it over one second.

**Done when.**

- Runtime tests: highest priority wins; a tie follows the rule in step 2;
  disabling the active camera falls back to the next; halfway through a
  blend the pose is halfway.
- A player test switches cameras from Lua.
- Save, reopen and Build keep priorities.

**Not now.** Spring arm and collision-aware camera rigs, camera shake,
several cameras drawn at once (split-screen, picture in picture). The sample
keeps its follow logic in Lua.
