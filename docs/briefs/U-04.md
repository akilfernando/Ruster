# U-04 · Inspector edits apply immediately

Lane UX · Size M · Depends on: nothing

**Outcome.** Changing a value in the Inspector changes the scene at once, as
in Unity and Unreal. There is no Apply button.

**Why.** In the user's own walkthrough on 2026-11-19 they expected edits to
take effect before pressing Apply
([record](../research/EDITOR-WORKFLOW-COMPARISON.md#human-walkthrough--2026-11-19)).
The [number field standard](../UX-STANDARDS.md#5-components) is: Enter
commits, Escape cancels, Tab moves on.

**Facts.** Checked 2026-11-27.

- `rot-editor/src/scene_editor/component_inspector.rs` begins: "Native v23
  Inspector widgets work on a draft; ComponentSession owns commits."
- Apply buttons use `Text::ComponentApply`: in `component_workspace.rs`
  (about lines 4127 and 4326) and in `component_material.rs`,
  `component_display.rs`, `component_player.rs`, `component_property.rs` and
  `component_sensor.rs`.
- `draft_dirty()` (`component_workspace.rs`, about line 1174) blocks other
  commands while a draft is open, for example
  `Action::Redo if self.draft_dirty() => return`.
- Drag-scrubbing a number already previews live and commits on release.
- The only component menu entry is Remove. Only Local Transform has Copy,
  Paste and Reset.

**Do.**

1. Commit a field when the creator presses Enter or Tab, when the field
   loses focus, when a drag ends, and at once for checkboxes, dropdowns and
   color pickers. One commit is one Undo step with a label naming the
   property.
2. Escape while editing restores the committed value. An invalid value
   shows one inline warning under the field and is not committed.
3. Remove the Apply buttons and the draft state from the Inspector, the
   material editor, Scene Display, Player settings, script properties and
   sensor binding. Keep Apply only in a true dialog that creates something.
4. Remove the `draft_dirty()` guards that existed only for the draft.
5. Every component header gets the `⋮` menu: Reset, Copy Component, Paste
   Component Values, Move Up, Move Down, Remove. Copy and Paste use an
   editor-owned buffer. Paste applies only to a component of the same type.
6. Multi-object editing follows the same rules. A commit across a selection
   is one Undo step.

**Done when.**

- No `Text::ComponentApply` button remains in the Inspector or the editors
  listed in step 3.
- In-process tests, one per component type: type a value and press Enter,
  then assert the scene value, exactly one new history entry and a correct
  Undo. One test each for Escape, an invalid value, a multi-object commit,
  Copy and Paste of a component, and Move Up.
- Scrubbing a 5,000-object selection stays under the
  [UI frame budget](../PARITY-PLAN.md#5-performance-budgets). Run
  `cargo test --release -p rot-editor --locked -- --ignored --nocapture
  benchmark_component_hierarchy` before and after.
- Saving and reopening keeps every edited value.

**Not now.** New field types. Object and asset reference fields for scripts
(`P4-12b`).
