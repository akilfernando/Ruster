# R-02 · Lift the prototype limits

Lane Repair · Size S · Depends on: nothing

**Outcome.** An ordinary small game no longer hits a hard limit in scripts,
animation, audio, input or the game HUD.

**Why.** [Decision A12](../PARITY-PLAN.md#4-architecture-decisions) says limits
are generous safety limits on untrusted input. These are still design limits
left from the prototype. Unity and Unreal have none of them.

**Facts.** Checked 2026-11-27. Raise each constant and every test that
pins the old value.

| Constant | File | Now | New |
| --- | --- | --- | --- |

**Do.**

1. Change the constants. Follow the compiler and the failing tests.
2. Search for the old numbers in error text and tests:
   `grep -rn "16 KiB\|exceeds16\|1\.\.{MAX_ANIMATION_TARGETS}" crates`.
3. Check each place that allocates from one of these limits up front
   (`grep -rn "with_capacity(MAX_" crates`) and allocate by actual size.
4. An infinite loop in a script must still stop with a readable Console
   error. Keep the existing test for that and note the new stop time.
5. Rerun both release benchmarks and compare with the numbers in the
   [budgets table](../PARITY-PLAN.md#5-performance-budgets):
   `cargo test --release -p rot-behavior --locked -- --ignored --nocapture bench_10k_script_updates_per_frame bench_1k_active_rigid_bodies`.

**Done when.**

- New tests pass: a 200 KiB Lua file loads and runs; a scene with 100
  Animators validates; an Animator binding with 200 targets validates; a
  three-minute WAV imports; 100 input actions validate; 40 HUD labels draw.
- Each limit still refuses input above the new value with a message that
  names the limit.
- Both benchmarks are within 5% of their previous numbers.
- The gate passes.

**Not now.** Mesh, texture and GLB size limits: they were raised at the Phase
2 exit and move again with cooked assets in Phase 5A. Streaming long audio
(`P4-07b`).
