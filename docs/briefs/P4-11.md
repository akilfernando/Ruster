# P4-11 · Physics essentials: capsule and mesh colliders, materials, contacts

Lane Play · Size M · Depends on: P4-S1

**Outcome.** A creator puts a Mesh Collider on level geometry, a Capsule on a
character, sets friction and bounciness, and reads where a collision
happened.

**Why.** Unity's collider set is Box, Sphere, Capsule and Mesh, each with a
physics material. Without mesh colliders an imported level cannot be walked
on.

**Facts.** Checked 2026-11-27.

- `ColliderShape` (`rot-scene/src/collider.rs`) is `Sphere { radius }` or
  `Box { half_extents }`. The Character Controller builds its own capsule
  internally (`rot-behavior/src/physics.rs`, about line 627).
- Colliders are created in `physics.rs` (about lines 529 to 531). Friction
  and restitution are never set, so every surface uses Rapier's defaults.
- `on_collision_enter(tr, props, other, host)` receives only the other
  object. `host.raycast` hits already carry `point` and `normal`.
- The viewport draws collider outlines only while collider edit mode is on
  (`rot-editor/src/scene_editor/component_collider.rs`).

**Do.** Follow [recipe 4.1](../ARCHITECTURE.md#41-add-a-component) for the
places a component change touches.

1. Shapes. Add `Capsule { radius, height }` along local Y and
   `Mesh { convex: bool }`. A Mesh collider uses the geometry of the Mesh
   Renderer on the same object; show an inline warning when there is none.
   Build `convex: false` as a Rapier triangle mesh and `convex: true` as a
   convex hull. A non-convex mesh on a Dynamic body is not supported by the
   solver: show the warning "Dynamic bodies need a convex Mesh Collider" and
   use the convex hull.
2. Material. Optional `friction` (default 0.5) and `bounciness` (default 0)
   on the Collider. Apply them when the collider is built and on live edit.
3. Contacts. Pass a fifth argument to `on_collision_enter`: a table with
   `point`, `normal` and `impulse`. Existing four-argument scripts keep
   working.
4. Inspector: the shape dropdown gains Capsule and Mesh with their fields;
   Friction and Bounciness rows; "Fit to Mesh" works for Capsule.
5. Scene view: draw the outline of every collider on the selected objects,
   in edit mode and in Play. Add a "Colliders" item to the viewport's view
   options that draws all of them.
6. Raycasts, shapecasts and overlaps hit the new shapes.
7. Add the shapes and fields to the component catalog and the MCP schema
   (`rot-mcp/src/component_tools.rs`).
8. Benchmark: a static triangle mesh of 100,000 triangles with 1,000 dynamic
   boxes resting and sliding on it, in release.

**Sample.** Replace the platforms' Box Colliders with Mesh Colliders. Add one
bouncy platform and one icy platform.

**Done when.**

- Runtime tests: a ball rests on a mesh floor; a capsule rolls off an edge;
  a bounciness of 0.8 returns at least half the drop height; friction 0 and
  friction 1 slide different distances; a contact reports a point within
  0.05 of the true touch point.
- The benchmark step is within the
  [4 ms physics budget](../PARITY-PLAN.md#5-performance-budgets).
- Save, reopen and Build keep every field. The player test covers a mesh
  collider.
- Screenshots viewed: Inspector with each shape, viewport with outlines.

**Not now.** Collision layers and the collision matrix (`P4-14`). Physics
material assets, heightfields, compound shapes authored by hand.
