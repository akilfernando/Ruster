# P4-09a · Game UI: text, images and bars

Lane Play · Size M · Depends on: P4-12b

**Outcome.** A creator builds a game HUD from objects in the Hierarchy: a
Canvas with Text and Image children, anchored to the screen, with a script
that changes the text and fills a health bar.

**Why.** Unity's UI is objects under a Canvas with a Rect Transform. The
current HUD is a separate dialog with four panels of text, which
[decision A1](../PARITY-PLAN.md#4-architecture-decisions) set out to end.

**Facts.** Checked 2026-11-27.

- The HUD is a scene field, `ComponentScene::hud` (`rot-scene/src/hud.rs`):
  panels on one of seven anchors, each a vertical stack of text and buttons.
  It is edited in Window, Game HUD
  (`rot-editor/src/scene_editor/component_hud.rs`) and drawn with egui in
  `rot-app/src/hud.rs`.
- HUD text can only show a script's state table. Only legacy `update()`
  scripts can write that table. A module script (`on_update`) cannot change
  any HUD text. See the two branches in `step_component_with_input`
  (`rot-behavior/src/component_runtime.rs`, about line 3095).
- There are no images, no bars and no fonts beyond egui's default.

**Do.** Follow [recipe 4.1](../ARCHITECTURE.md#41-add-a-component) for each
component.

1. `UiCanvas` on a root object: `sort_order` (default 0) and
   `reference_height` (default 1080). Everything under it scales by window
   height divided by reference height.
2. `UiRect` on each UI object: `anchor_min`, `anchor_max` (each 0 to 1 of
   the parent's rectangle), `offset_min`, `offset_max` (pixels). The
   rectangle is `parent.min + anchor * parent.size + offset` for each
   corner. A canvas child's parent rectangle is the screen. This is Unity's
   Rect Transform.
3. `UiText`: `text`, `font_size` (24), `color`, `align_x`, `align_y`, `wrap`.
4. `UiImage`: optional `texture` asset, `color`, `fill` 0 to 1 and
   `fill_direction` (left, right, up, down). No texture draws a solid color.
5. Draw in `rot-app/src/hud.rs` after the 3D view, in Hierarchy order, later
   siblings on top. Disabled objects and their children are skipped. The
   object's 3D Transform is ignored for UI objects.
6. Lua handles: `UiText` has `text`, `set_text(s)`, `set_color(c)`.
   `UiImage` has `fill`, `set_fill(x)`, `set_color(c)`.
7. Editor: Object, UI creates Canvas, Text or Image, adding a Canvas when
   there is none. The Inspector shows an anchor preset dropdown (the sixteen
   Unity presets) and four numbers labelled as Unity labels them: Pos X, Pos
   Y, Width, Height, or Left, Right, Top, Bottom on a stretched axis.
8. The Game view shows the UI in edit mode and in Play, at the chosen
   aspect.
9. The old HUD keeps working and draws on top. Do not convert it.
10. Add to the component catalog, the MCP schema and `docs/LUA-API.md`.

**Sample.** A coin counter top-left, a three-heart health bar using `fill`,
and a "Level Complete" text shown on reaching the flag.

**Done when.**

- Layout tests: the rectangle formula for point anchors and for stretch, at
  16:9 and 4:3; nesting two levels deep; scaling at 720 and 1440 high.
- Runtime test: a module script changes a text and a fill.
- 500 elements lay out and paint in under 0.5 ms on the CPU in release.
  Put the number in the commit.
- Screenshots of the Game view at 16:9 and 4:3 and of the Inspector, viewed.
- A real AI client adds a text to the canvas through MCP.

**Not now.** Buttons, focus and gamepad navigation (`P4-09c`). Dragging
rectangles in the viewport, layout groups, custom fonts, sliced images,
scroll views, input fields, world-space UI.
