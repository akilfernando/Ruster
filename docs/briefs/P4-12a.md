# P4-12a · Script essentials: modules, random, time, lifecycle

Lane Play · Size M · Depends on: R-02, R-03

**Outcome.** A creator splits game code across files with `require`, uses
random numbers and a clock, runs code when an object is destroyed or
disabled, and can destroy any object.

**Why.** Every Unity script uses other classes, `Random`, `Time` and
`OnDestroy`. Without shared modules a game's code cannot be organized.

**Facts.** Checked 2026-11-27.

- Each script is one isolated chunk. The environment has `math`,
  `coroutine`, `table` and `string` and no `require`
  (`rot-behavior/src/lib.rs`, about line 615; the whitelist is in
  `lua_component.rs`, about line 228).
- `math.random` is not exposed. There is no time function; `dt` arrives as a
  callback argument.
- `host.destroy` refuses authored objects: "destroy requires a live or
  pending runtime-spawned object" (`lua_component.rs`, about line 3782).
- Callbacks are read in `component_module` (`lua_component.rs`, about line
  3817): `on_start`, `on_update` and the four physics callbacks.
- A build embeds each used script in the scene's `script_files`. Live reload
  on save exists in the editor (`reload_component_file`,
  `component_runtime.rs`).

**Do.**

1. `require("Scripts/util")` loads `Assets/Scripts/util.lua` once per Play
   session and returns its value. Paths are relative to `Assets/`, with no
   extension. Refuse anything outside `Assets/`. A cycle is an error that
   names both files. Saving a module reloads it and every script that
   required it.
2. Build packages every `.lua` file under `Assets/`, so `require` works in
   the player. Add them next to `script_files`, as an optional field.
3. `math.random` and `math.randomseed`. Seed with a fixed value at the start
   of Play so runs and Play Checks repeat exactly. `host.randomize()` seeds
   from the operating system when a creator wants variety.
4. `host.time()` is seconds since Play started, `host.frame()` is the tick
   count, `host.dt()` is the tick length.
5. New callbacks with the same arguments as `on_start`: `on_destroy`,
   `on_enable`, `on_disable`. `on_destroy` runs when the object is destroyed
   and when Play stops.
6. `host.destroy(obj)` works on any object. Play always starts from the
   saved scene, so nothing authored is lost.
7. `host.find_all(name)` returns every match as an array.
8. Document each addition in `docs/LUA-API.md`. The drift test from `R-03`
   must pass.

**Sample.** Move shared helpers into `Assets/Scripts/util.lua`. Coins call
`host.destroy`. Spawn one coin at a random spot each time one is collected.

**Done when.**

- Runtime tests: require returns the same table twice; a cycle errors; a
  module edit reloads its dependents; two runs produce the same random
  sequence; `on_destroy` runs once; an authored object can be destroyed and
  is back after a reset.
- The player test loads a script that requires a module.
- The 10,000-script benchmark is within 5% of its previous numbers.
- Script errors inside a required module name that module's file and line.

**Not now.** Tags, object and asset reference properties, spawning a prefab
asset (`P4-12b`). A package manager for Lua libraries.
