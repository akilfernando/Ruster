# P4-08a · Mouse look, scroll, cursor lock and modifier keys

Lane Play · Size M · Depends on: P4-S1

**Outcome.** A game reads mouse movement, all three mouse buttons, the scroll
wheel and Shift, Ctrl and Alt, and can lock and hide the cursor.

**Why.** Unity's default input map has Mouse X, Mouse Y, Mouse ScrollWheel
and Fire1 to Fire3. A third-person or first-person camera needs them.

**Facts.** Checked 2026-11-27.

- `ActionKind` (`rot-scene/src/input.rs`) is `Button { keys, primary_mouse }`
  or `Axis1d { negative, positive }`. Keys are the `InputKey` list built by
  the `logical_keys!` macro: letters, digits, arrows, function keys, Space,
  Enter. There are no modifier keys, no other mouse buttons, no mouse
  movement and no scroll.
- `host.axis(id)` returns a whole number from keys.
- `KeyEventAccumulator` (`input.rs`, about line 367) turns key events into
  one `ActionFrame` per tick. It is fed from `rot-app/src/host.rs` (about
  line 902) in the player and from
  `rot-editor/src/behavior_ui/runtime_input.rs` in editor Play.
- The Input Actions editor is `rot-editor/src/input_ui.rs`, under Project
  Settings.
- Play gives the Game view the keyboard on click and Escape gives it back.

**Do.**

1. Keys: add LeftShift, RightShift, LeftCtrl, RightCtrl, LeftAlt, RightAlt to
   `InputKey`.
2. Buttons: replace the `primary_mouse` flag with a list of mouse buttons
   (Left, Right, Middle). Keep reading the old flag so saved scenes load.
3. Axes: `Axis1d` gains an optional `mouse` source (`x`, `y` or `scroll`) and
   a `sensitivity` (default 1.0). `host.axis(id)` returns a number with a
   fraction. Mouse movement between two ticks is summed and delivered once.
4. `host.mouse_position()` returns pixels and a 0 to 1 pair inside the Game
   view. `host.set_cursor_locked(bool)` and `host.set_cursor_visible(bool)`.
   When locked, movement comes from raw mouse motion, not from position.
5. In editor Play, lock applies only while the Game view has the keyboard.
   Escape always unlocks and shows the cursor, before anything else.
6. Input Actions editor: a row can bind a mouse button, a mouse axis or a
   modifier key. "Press a key" capture accepts mouse buttons.
7. Player: lock and visibility work in windowed and borderless fullscreen.
8. Play Checks record and replay mouse axes like any action value.
9. Add the new sources to the MCP input schema and to `docs/LUA-API.md`.

**Sample.** Mouse orbits the follow camera with the cursor locked. Scroll
zooms. Shift is a run modifier.

**Done when.**

- Tests in `rot-scene`: movement summed across events inside one tick; a
  right button press gives pressed, held and released in order; an old scene
  with `primary_mouse: true` loads and behaves the same.
- A player test drives a mouse axis for 60 ticks and asserts the camera yaw.
- In editor Play, Escape unlocks the cursor from every state. Check this in
  an in-process test, because `ui_drive.py` cannot hold focus.
- Screenshots of the Input Actions editor with a mouse axis row, viewed.

**Not now.** Gamepad and rebinding at runtime (`P4-08b`). Touch.
