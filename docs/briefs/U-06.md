# U-06 · Console and script debugger

Lane UX · Size M · Depends on: U-01

**Outcome.** A script error shows in the Console and a double-click opens the
file at the line. A creator can set a breakpoint, stop on it, read the
variables and step.

**Why.** In the 2026-11-19 walkthrough the user asked for clickable error
details and source navigation
([record](../research/EDITOR-WORKFLOW-COMPARISON.md#human-walkthrough--2026-11-19)).

**Facts.** Checked 2026-11-27.

- `rot-editor/src/console.rs` has `Entry.location: Option<(String, u32)>`
  and `Request::OpenSource`, but production code never fills in `location`,
  and the caller drops the request: `let _ = self.console.ui(ui);`
  (`scene_editor/component_workspace.rs`, about line 3521).
- Script errors show only in the play toolbar, with an "Open Error Line"
  button (`behavior_ui.rs`, about line 3413). That button already opens the
  configured external editor at a line. Reuse its code path.
- The Console has level filters with counts, Clear and Collapse. It has no
  search and no Clear on Play.
- The debugger backend works: `rot-behavior/src/debug.rs`
  (`DebugHandle::set_breakpoints`, `stop`, `resume`; `StopSnapshot` with up
  to 8 frames and 64 locals). It is reachable only through MCP
  (`behavior_ui/runtime_debug.rs`, about line 360). There is no panel, and
  the `ScriptDebugger` command does nothing.
- The worker's debugger controls never block. They return
  `DebugRequestError::Busy` when the worker thread holds a lock at that
  instant. A caller retries on the next frame; it does not show an error.

**Do.**

1. Fill in `location` for script logs, warnings and errors. Send script
   errors to the Console as well as the toolbar.
2. Handle `Request::OpenSource` by opening the external editor at the line.
3. Console: a search field (Ctrl+F focuses it, Escape clears then leaves),
   a Clear on Play toggle that is on by default, and a detail area that
   shows the selected entry's full text.
4. Add a Script Debugger panel, opened from Window and by the
   `ScriptDebugger` command, docked beside Console:
   - A breakpoint list. Add one by choosing a script and typing a line.
     Remove and enable or disable each.
   - When stopped: the script and line, the call stack, and the locals of
     the selected frame as an expandable tree.
   - Continue (F5), Step (F10) and Stop buttons with those shortcuts,
     remappable like every command.
   - While stopped, the Play controls show Paused and the status bar says
     "Stopped at `<script>`:`<line>`".
5. Breakpoints are editor state. Save them with the project's editor state,
   not in the scene file.

**Done when.**

- In-process tests: a script that calls `host.log` produces an entry with a
  location; a script error produces an Error entry with a location; the
  open request reaches the launcher with the right path and line.
- Through the real worker: set a breakpoint, press Play, assert the stop and
  one named local, Step once, assert the next line, Continue.
- Screenshots of the Console with an error selected and of the debugger
  stopped on a line, viewed at 1280×800.
- `tabwalk` reaches every debugger control.

**Not now.** Setting breakpoints from the external editor. Watch
expressions and editing variables. A profiler (Phase 5A).
