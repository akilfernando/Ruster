## Selected design

This repair applies to the generic Scene Host used by no-argument and `--scene` launches. The retained legacy logistics `--scenario` EditorApp still services its legacy bridge through UI; expanding that sample frontend is outside this V2a creator workflow. Do not describe this as a verified background guarantee for every legacy tool or frontend.

Service bounded owner-thread nonvisual work through App::logic on demand. Split recovery scheduling and export completion/publication from drawing their dialogs; poll asynchronous owner completions and retain exact document/lease/generation authority. Export publication runs only after fresh human input/close priority and after same-tick bridge cancellation, preserving the existing identity/guard checks. Genuine unprocessed human authoring input and close/cancel retain priority, observed through raw_input_hook rather than stale Context input/time. A shared admission gate permits at most one bridge request per servicing tick/frame, including visible logic/UI/multipass paths. Render/capture may wait for actual painting and must report or expire truthfully; never fake focus, UI counters or paint completion.

Retain the existing paint-fenced retirement bundle and add exactly one fixed immediate-retirement bundle, using the existing bounded worker and its single retirement in flight. Track conservative exposure for accepted store and authored/preview/reset map roles, marked only by real UI passes. Exposure must cover the actual callback construction point: an adoption before the viewport in the same pass cannot leave newly rendered owners classified as never exposed. Likewise, replacement after the viewport must retain owners already captured by that pass. Begin-frame bookkeeping alone is insufficient unless this ordering is separately guaranteed. Replacing an exposed owner puts it behind the existing later-root-frame fence; replacing a never-exposed owner uses immediate worker retirement. Authored Session/save-request payloads do not contain callback-visible mesh/texture Arcs and may retire immediately. Rejected never-adopted candidates likewise need no artificial paint fence, subject to inspection of their actual owning types.

The original last-painted owners remain retained while hidden. Each subsequent never-painted version must drain the immediate slot/worker acknowledgement before another candidate is admitted. No list of per-operation snapshots or unbounded queue is permitted. Real UI reappearance drains eligible old fenced owners at the existing root-frame boundary before marking new exposure. A discarded UI pass is conservatively treated as exposure where callbacks might retain ownership; logic-only work never advances the fence.

Maximum roles are accepted state, one prepared/result candidate, one fixed paint-fenced bundle, one fixed immediate bundle and one existing worker retirement in flight, plus existing bounded channel roles. This adds one bounded retirement bundle to0030's retained ownership envelope. An occupied required role or immediate/inflight cleanup supplies backpressure; read-only observations remain available. If UI reappearance exposes current owners before an already-authorized result arrives, the existing single candidate/result owner may be held by the controller until required slots are available, while retirement acknowledgements continue to drain. This transfers the sole candidate role rather than admitting another payload or adding a result queue; new admissions remain blocked. Eligible real-paint fence handoff takes priority over immediate cleanup. The implementation must verify which roles coexist rather than treating this inventory as measured memory usage.

A committed Save completes only after required nonvisual retirement/recovery acknowledgement, or the established failed-worker cleanup handoff with its explicit committed warning. A handoff is not a claim that every drainer destructor has already executed. It need not wait for retained original painted owners. Receipts/observations must explicitly distinguish paint cleanup still pending from nonvisual follow-up pending; do not imply all resource cleanup finished. Automatic New/Close continuations retain the actual fence-drain requirement. Existing authority, expiry, post-publication receipt and committed-warning semantics remain.

## Alternatives and rationale

- Forcing focus or continuous hidden painting would mask model-service coupling and interfere with normal creator workflows; rejected.
- Immediate retirement of all old stores/maps could make a later callback drop the final CPU owner on the foreground thread; rejected.
- Nonvisual retirement of Session alone fixes repeated same-root saves but leaves hidden content/root-changing SaveAs incomplete; retained only as a safe component.
- Acknowledging Save while every later hidden content/save stays busy would narrow first-class MCP parity; rejected as the complete solution.
- Per-operation retirement queues or a new collector/thread expand memory/architecture unnecessarily; rejected in favor of fixed roles and existing worker backpressure.

## Consequences and acceptance

The controller becomes more explicit about exposure and cleanup phases. The additional fixed bundle increases bounded retained memory; final resource evidence must account for it. No lower memory, latency, CPU or completed capability claim follows from this decision.

Pending-human guards, expired-request nonexecution and truthful capture waiting remain required. Reuse unchanged Scene/renderer/runtime evidence only where these edits do not alter its inputs.
