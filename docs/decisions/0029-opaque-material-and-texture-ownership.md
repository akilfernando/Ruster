# 0029 Opaque material and texture ownership

Date:2026-11-05. Status: **selected V1 design at the early checkpoint; implementation and end-to-end feasibility remain incomplete.** Root reconciled source inspection with independent Astra material/history review and Sol's actual cached-decoder probe. This extends0006/0008/0016/0027; it does not claim completed texture support. [V1 contract](../plans/V1-TEXTURED-MATERIALS.md) owns acceptance.

## Context and alternatives

At selection, Scene5 owned flat objects, object colors and reversible visual edits. The separate asset catalog owned mesh sources and explicit refresh; OBJ discarded validated UV indices. Preview/behavior/runtime clone `Scene`; runtime resources and accepted-source exports are mesh-only. We need reusable materials and real textures across all of those paths, without a project database, ECS or new renderer backend.

Choose a bounded `Scene.materials` map and optional `Object.material` stable ID. A separate file/catalog material would place ordinary edits outside scene Undo and introduce a cross-file transaction problem. Putting materials in behavior `Authoring` would require a parallel visual snapshot at every plain Scene consumer. Cross-scene material libraries remain future scope, not an implicit promise of this scene-owned design.

## Authored state and commands

- Scene6 introduces at most64 scene-owned opaque materials. Each has an optional display name, finite linear RGB tint in0..1, optional base-color texture asset ID, and bounded nearest/linear filtering plus repeat/clamp addressing. No image bytes, filesystem paths or GPU objects enter scene state.
- Object material assignment must resolve inside its Scene. External texture references remain syntactically valid authored data even when unavailable, with diagnostics and explicit repair; faithful runtime/export rejects unavailable required content.
- Base color is `object.color.rgb × material.tint × sampled_sRGB_texture_decoded_to_linear`. Absent material/texture factors are white; an assigned unavailable texture uses an explicit diagnostic placeholder rather than silently succeeding as untextured. Preserve existing object RGBA data and commands; output stays opaque. Assignment never silently resets an object's existing tint. Show the object field as Object tint when assigned and make shared-material editing clear.
- Create/edit/copy/delete material and object assignment use existing validated Scene history. Create-and-assign is one transaction. Shared edits affect all referencing objects; object duplication retains the reference. Delete rejects currently referenced materials; historical IDs stay reserved so Undo is valid. Material edits do not undo source imports/refreshes.
- Empty maps and absent object references are omitted where possible to preserve legacy untextured fingerprints. Strictly reject Scene6 fields/deltas under old version labels, including nested history. Preserve supported1–5 values/revisions/history; explicit Save writes6. Include materials in current and Undo/Redo-reachable byte accounting and texture references in cross-root SaveAs guards.
- Clipboard operations must carry material definitions and remap references across documents coherently; matching project roots alone do not establish identity. Do not silently paste the wrong appearance. Preview freezes texture snapshots together with scene and mesh snapshots until Reset.

## Mesh and texture assets

- Preserve complete OBJ UVs by face corner, including seams/negative indices, without geometry deduplication. Use an optional separate UV stream on `Mesh`, with exactly one2D coordinate per expanded vertex when present; absent or partially mapped legacy meshes retain geometry and a clear “UVs missing/incomplete” limitation. Textured assignment/runtime validation requires a complete set. This avoids adding per-vertex optional-value overhead to legacy CPU geometry. Retain raw repeat coordinates; flip V exactly once for top-row-first images.
- Mesh cache3 adds UVs. Read cache1/2 as legacy geometry without UV information; recover UVs by reparsing unchanged accepted source when available, not by treating a valid old cache as proof there were no UVs. Preserve legacy cached geometry when source is missing. Legacy JSON checksum validation must use the original serialized representation. Keep existing generated flat-normal semantics for this slice. Increase the logical mesh payload cap from32MiB to48MiB when counting the added UV stream, so recovering UVs does not reject a previously supported near-cap geometry set merely for its new attributes; separately report the extra CPU/GPU bytes and measure them. This is a compatibility bound, not a performance-budget pass.
- Catalog2 distinguishes mesh/texture entries and shares identity, revision/baseline/advisory-lock/source-confinement rules. Read catalog1 without rewriting it on open; mutation is the migration boundary. Preserve kind through rename and forbid changing a registered asset's kind via rename.
- Initial texture route: ordinary nonanimated, noninterlaced8bit RGB/RGBA PNG, normalized to opaque RGBA8. Ignore alpha for appearance while retaining RGB even at source alpha0. Accept untagged/sRGB base-color input; reject unsupported profiles/transfer encodings explicitly rather than silently reinterpret them. Other image encodings are separate increments.
- Selected initial bounds: encoded PNG at most8MiB; edges at most2048; complete decoded mip payload at most24MiB per texture and64MiB across accepted project textures; at most64 combined mesh/texture catalog records. These are bounded starting choices, not measured budget passes. Check source/header/output and allocation arithmetic independently of the decoder's best-effort internal limits. Old snapshots/candidates/GPU retirement can exceed retained-payload accounting during refresh and must be measured.
- Immutable `Arc<Texture>` snapshots contain dimensions and a complete checked mip chain. Generate RGB mips in linear light, then encode sRGB; account for odd-dimension coverage. Reuse unchanged snapshots. Persist a bounded checksummed accepted texture cache for last-good reopen. Missing both source and usable cache is irrecoverable and must remain visible.

## Rendering and delivery

Keep the shared Vulkan/wgpu route. Retain texture/bind resources by immutable content identity, share small sampler variants, bind the selected texture/sampler per mesh/material-compatible draw group and avoid repeated decode/upload on ordinary redraw. White texture fallback handles deliberately untextured materials. Selection highlighting is presentation-only and follows texture/tint combination so black texels can still be selected visibly.

Preserve existing camera binding and shader input locations0–9; append new UV/material inputs and texture bindings rather than reinterpret old locations. Review actual old WGSL compilation/rendering in the feasibility path. Custom shader output remains custom; default-material appearance claims apply to the supported material shader contract, and unsupported interfaces must fail visibly while retaining the last-good pipeline. A source-text marker alone is not ABI validation.

Extend application `Content` with immutable textures and an explicit resolved-material dependency check. Preserve the existing untextured constructor path for ordinary code-first consumers where possible. Extend versioned launch/template/packager capability contracts and the accepted-source closure from objects→materials→texture IDs. Include exact accepted PNG source bytes; changed external bytes require explicit Refresh. Reject missing/invalid required sources rather than package a substitute. No arbitrary file/process authority is added to MCP.

## Evidence, consequences and remaining checkpoint

Sol's rustc-only probe `/tmp/ruster-v1-asset-probe-png-20261105` linked the existing cached png0.18.1 library in0.42s: RGB/RGBA row order and opaque normalization pass; representative invalid encoding/CRC/truncation/size rejections pass; a linear-light black/white mip produces188 rather than128. This does not prove production profile/APNG handling, full mip generation, cache migration, GPU behavior or export.

The remaining early checkpoint must exercise the actual asset→shared GPU→exported-runtime path and inspect its result before broad UI work. Stop/replan if this needs a consequential new subsystem. UV cache/schema/runtime evolution and shader compatibility are real maintenance costs, not a free field addition. Measure baseline/candidate import, mip work, rendering and retained/refresh costs before calling the design efficient; no performance advantage is established by this decision.
