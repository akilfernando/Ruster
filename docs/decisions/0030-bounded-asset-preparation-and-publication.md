# 0030 Bounded asset preparation and publication

Date:2026-11-05. Status: **selected implementation direction; not implemented or accepted as verified behavior.** Agent-selected root/Astra response to the measured V1 dependency; the user authorized adjusting short-term work for quality and efficiency. Extends [0029](0029-opaque-material-and-texture-ownership.md), without changing its formats or adding a product capability. [V1](../plans/V1-TEXTURED-MATERIALS.md) retains all acceptance gates.

## Context and alternatives

The release baseline observes2048² import/unchanged Refresh/changed-unaccepted open medians219/222/225ms; accepted-cache open still takes32ms. These are operation timings on a non-isolated powersave host, not measured UI latency. Current editor commands and catalog-open paths perform this work synchronously. Actual bridge `crates/ruster-editor/src/bridge.rs` holds its Pending mutex through command dispatch, serializing timeout against mutation. Simply spawning those mutations and returning would permit an expired request to commit later.

Choose one bounded serial asset worker and two-phase preparation/publication. Keeping synchronous calls fails the responsiveness requirement. A permanently worker-owned AssetStore would require replacing the catalog-view API across content search, behavior, material validation, capture and export without evidence that V1 needs that broader change. Taking `self.assets` out temporarily is unsafe: existing None semantics mean unavailable content and can clear accepted render snapshots. A general task scheduler, asset database and streaming system remain excluded.

Primary source accessed2026-11-05: [Godot background loading](https://docs.godotengine.org/en/stable/tutorials/io/background_loading.html) uses request/status/adoption and warns that fetching unfinished loading work blocks. This supports nonblocking adoption; Ruster's catalog mutation/deadline protocol below is its own design, not supplied by that source.

## Ownership and transaction contract

1. Capture root, exact catalog baseline/revision, source/operation identity, immutable accepted payload Arcs and budgets. Allow one outstanding candidate, with no unbounded queue or automatic retry. Worker performs source reads/hashing, decode/mips, payload comparison and cache preparation. Rejected payload/buffer destruction belongs off the UI thread.
2. Editor retains the accepted store and viewport snapshots throughout preparation. Before publication, revalidate session generation, scene/catalog identities and human draft/dialog ownership. A request's own asset modal must be distinguished from an unrelated modal. Scene edits during preparation may reject the candidate; do not silently change the admitted revision contract.
3. Publication authorization reserves the root/catalog until acknowledgement. Worker rechecks source identity and exact disk baseline under the catalog lock, writes cache before catalog and reports success/failure. Painting, navigation, inspection and progress feedback continue; conflicting mutations/root replacement must wait or reject clearly. Reserve the admitted scene/root/catalog identity: relevant authoring changes and new drafts cannot invalidate it between commit authorization and acknowledgement. A committed old-root operation must be acknowledged before retiring that root; never discard its result as stale and pretend no disk mutation occurred.
4. Adopt returned metadata/payloads and invalidate Content search/render identities together before completing the originating request. Failed Refresh may change diagnostics without advancing catalog revision. Preview scene/mesh/texture snapshots stay frozen until Reset. Preserve source/catalog failure atomicity and last-good acceptance.
5. MCP retains existing operation names and terminal result shapes. Introduce an explicit deferred lease with states equivalent to Queued, Preparing, Committing, Completed and Expired/Rejected. Check expiry atomically at commit authorization. Expired preparation cannot publish. After authorization a timeout cannot roll back a commit; lost replies retain the existing unknown-outcome/inspect-before-retry contract. UI never waits on a mutex held during worker I/O. Preserve bounded output and the existing2s bridge/3s adapter deadlines unless a separately documented change is required.
6. Catalog opens must use the same nonblocking ownership principle: initial editor construction (create a paintable loading shell before starting catalog work), recovery restore, recovered-content Retry and SaveAs destination preparation. Keep the old document or explicitly show loading until ready; unresolved placeholders are not successful completed loads. Prepare a destination before SaveAs disk commit and adopt it only after saving succeeds. Preserve recovery's origin and unsaved-copy authority.

## Independent work elimination

A matching accepted source hash plus an existing accepted texture Arc can skip decode/mips on Refresh while retaining cache repair, status, conflict and revision guarantees. Mesh Refresh retains legacy UV recovery. Changed-but-unaccepted PNG open may report changed/unaccepted status without generating a discarded mip chain; specific format validation is deferred to explicit Refresh. Both are independent optimizations, not substitutes for first-import/cache-rebuild responsiveness.

## Acceptance and consequences

Working engineering budgets, selected before retaining the async design: foreground enqueue/adopt p95 each at most5ms for the named V1 workload, no decode/mip/fsync on the UI thread, one candidate/no queued payloads, and longest measured focused editor frame gap at most50ms while a2048² import runs. Measure under named matching conditions and retain raw samples; these are V1 investigation/acceptance targets, not user SLAs or claims of current performance. A miss requires investigation and explicit reassessment, not hiding work or reducing quality. Report total operation time separately and investigate any matched median regression over10%, acknowledging sampling noise. Derive and check candidate/accepted/cache/GPU overlap from actual allocations and encoded-size pressure before claiming a memory budget pass;64MiB retained decoded pixels alone does not bound the whole process.

Extend existing owning cases for preparation/publication source/catalog changes, write failures, budget rejection and stable Arcs. Add narrowly justified bridge ordering coverage for expiry before/during preparation and immediately before commit, reply loss, exactly-once publication and nonblocking completion. Editor integration covers human drafts/root replacement with equal counters, close/cancel in both phases, recovery and failed cross-root SaveAs. Required native MCP completion and human keyboard-while-working evidence remain open until normal desktop access. Final source/render/export/history/recovery gates remain unchanged.

This is an explicit V1 dependency replan. Implement in reviewable stages, reassess on the existing first-runnable/90-active-minute cadence, and stop/replan if this bounded controller expands into a general subsystem. No lights, PBR, import formats or new milestone are added.
